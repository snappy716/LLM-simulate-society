# DeepSeek 真实 API 三日无人干预验收

## 结论

2026-09-08，在 `6805f66` 游戏运行时代码上完成真实模型三日模拟及同种子离线对照。**Key 有效，20 名深度 NPC 全部参加跨日规划，模型选择可以落到实际行动；尚未证明极高自由度或显著更强的故事涌现。** 正式适配器的默认设置存在已复现的 DeepSeek V4 兼容性问题，不能把本轮测试配置的成功当作正式游戏开箱即用。

本轮只新增测试工具与验收证据，没有修改游戏逻辑、UI、个人接口配置、调用配额或存档。没有保存 Key，没有上传本轮变更。没有打开可见 Godot 窗口。

## 条件与边界

- 官方服务 `https://api.deepseek.com`，鉴权后的模型列表包含 `deepseek-v4-flash`；本轮使用它，不使用第三方模型别名。
- 校园 200 名 NPC，其中基础 20 名接入真实模型；本轮没有额外觉醒好友。好友叠加机制另有离线 Godot 专项回归，不能算作本轮真实模型人数扩容验收。
- 种子 42。两组均先用规则推进到第 1 天凌晨，再完整模拟第 2、3、4 天，共三次过夜、十二个时段。玩家只推进时段，不做任务、不聊天、不修改关系。最后另在分离状态上抽测两名 NPC 的玩家对话。
- 真实组使用原通用 HTTP 适配器和原状态校验，但**测试传输层明确加上 `thinking: {type: disabled}`，测试超时为 30 秒**。这两个设置未进入正式配置。游戏中不设调用次数限制；测试仅在连续三次接口失败时中止整轮，防止失败请求持续花费。
- 单次、单种子、短窗口对照，只能发现差异和缺陷，不能作为统计显著性或长期叙事质量证明。逐回合没有注入假模型响应。
- 两项 Godot 后台流程仍使用离线/假提供者，验证好友及跨日 UI 的回归；真实模型多日验收在共享 Python 内核完成，未验证 Godot 窗口里的真实模型配置闭环。Windows 实机未测。
- 配套 Python 认知、每日计划、额外好友与测试工具回归共 18 项通过，见 [测试日志](validation/live-deepseek-20260908/python.log)。本轮没有重跑上一轮全部 575 项测试；游戏运行时代码未修改。

## 接口兼容性发现

默认 V4 思考模式的真实日程请求，HTTP 返回 200，但 `finish_reason=length`，512 个输出 Token 全为 reasoning Token，`content` 长度为 0，原适配器按无效 JSON 拒绝。见 [原配置日程探针](validation/live-deepseek-20260908/default-plan-probe.json)。简单问候探针可以偶尔成功，不能据此推断完整日程可用。

非思考配置下，60/60 日程请求合法，240/240 时段计划来源为 LLM；运行时统计接口错误、响应拒绝、回退和预算拦截均为 0。该参数的含义与默认行为已核对 [DeepSeek 官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

前置修复应是**可配置的提供者请求选项/思考开关**，而不是对所有兼容接口无条件硬编码 DeepSeek 私有参数；同时需要在 UI 中明确显示配置、失败原因与实际模型。不能静默退回规则却显示“LLM 已正常工作”。

## 实测结果

| 指标 | 真实 LLM 组 | 同种子离线组 |
|---|---:|---:|
| 完成的日程请求 | 60，20 人 × 3 天 | 0 |
| NPC 互动事件 | 129 | 129 |
| 情报分享事件 | 45 | 36 |
| 完成任务 | 69 | 70 |
| 私人交易成交 | 74 | 72 |
| 个人目标推进事件 | 34 | 33 |
| NPC 夜间任务执行事件 | 11 | 12 |

- 240 个 LLM 时段选择中，67 个选择不是候选排序第一项，且行动/地点/参数确实有差异，不只是换了编号。
- 20 名深度 NPC 的 240 个时段都有实际活动完成回执；212 个与计划的行动和地点一致。28 个不一致中，21 个因必要物品短缺被采购规则覆盖，6 个因已接论坛任务覆盖，1 个未记录细分决策原因。后者是解释性缺口，不能把所有差异都笼统称作正常。
- 与离线组比较，深度 NPC 有 65 个实际活动/地点时段不同；整个校园在 2,398 个至少一组有活动完成回执的时段样本中有 161 个不同。**不将后续整个世界的差异都归因于某一个模型决定**：两组轨迹分叉之后，规则、资源与 RNG 消耗也会不同。
- 129 次 NPC 互动中，只有 2 次意图选择来自 LLM、3 次措辞来自 LLM。绝大多数依然是规则互动。20 名“参加日程推理”不等于 20 名“都在主导社交故事”。
- 两组都完成了 6 个需求衍生任务、4 个互动线索衍生任务。这说明无玩家时已有需求→发布→承接→结算的系统链路，但它在离线组也成立，**不是此次 LLM 新创造的能力**。

## 时间与调用消耗

- 真实组过夜分别 33.147、35.485、28.221 秒；日内 0.270～0.475 秒，日内后台 API 调用为 0。
- 正式三日模拟消耗 65 次请求：60 次日程、2 次社交意图、3 次 NPC 社交措辞。
- 加上本轮非思考连通探针与两次玩家对话抽测，该批记录共 68 次请求，输入 100,175 Token、输出 7,067 Token，总计 107,242 Token。
- 此外有 3 次默认配置诊断请求：最初一次仅留存失败类别和耗时，Token 未留存；另外两次分别记录 232 与 1,920 Token。因此本轮合计 **71 次生成请求尝试，已记录至少 109,394 Token**，不把最初未记录的消耗算作零。不含免费模型列表读取；未查询账户账单，实际扣费以服务商账单为准。
- 本轮未继续延长到七天：兼容性和社交覆盖不足已经明确，再增加天数不能代替针对性修复。

## 具体可追踪的行为与质量问题

1. 第 2 天上午，林晏如与朱云舟的交流被拒绝，产生冲突/怀疑变化；第 3 天与邓清越的交流被接受，产生熟悉度、尊重和情报分享回执。两次都是 LLM 选择意图，但**不能仅凭先后顺序称第二次由第一次导致**。
2. 深度 NPC `campus_student_087` 在第 3 天晚上和凌晨实际执行知识阅读，并分别推进两项已有异常研习目标。这是可执行的长期目标机制；目标模板不是本轮模型发明的。
3. 需求衍生任务完成后，发布者的好奇需求有实际下降，奖励和关系也实际结算。详见 [精选事件回执](validation/live-deepseek-20260908/examples.json)。
4. **社交身份混淆**：第 2 天意图理由把行动者自己的名字当成同处对象；第 3 天实际对象是邓清越，但理由提到了上一日的朱云舟。程序校验 ID，所以未发生越权换目标，但人物主观解释不可靠。输入给当前身份/目标缺少明确姓名映射，历史记忆却含姓名，是应优先核查的上下文设计问题。
5. **空泛/复述对话**：对深度 NPC 说“你好，最近在校园里过得怎么样？”，模型原样复述同一句；普通 NPC 回答“还行吧，就是最近有点忙，你呢？”。两次协议正确、来源为真实模型，但不足以证明人物有鲜明个性。该抽测调用运行时对话方法，未经过 Godot 面对面 UI 或手机命令，亦未携带事实白名单，不能代替完整交互验收。

## 下一步建议（尚未实施）

1. 修复正式接口配置：提供者选项、非思考开关、可观察的截断/超时提示、失败 Token 统计，并用 Godot 配置页面完成一次真实跨日闭环。
2. 修复身份与上下文：显式的本人/对象 ID＋名字，区分当前对象与历史对象，提供合法的个体经历，针对复述和凭空套用历史写质量测试；结构校验不能替代语义验收。
3. 丰富夜间规划中的社交意图：计划包含想找谁、为什么、前置条件和失败后方案，白天通过现有合法行动执行，不恢复每个时段完整 LLM 推理。让更多深度 NPC 真正有跨人、跨日的行动链。
4. 将模型能影响的目标、合作、求助与任务后续扩展成可校验的结构化意图，再跑多个种子的七日对照，并用事件回执检查因果链。不要把任务数量或聊天句数当作故事质量。
