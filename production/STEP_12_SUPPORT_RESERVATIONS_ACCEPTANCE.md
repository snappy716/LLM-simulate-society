# 第 12 步：支持活动与既定预约的兼容验收

2026-09-10。接续已上传的自然相处提交 `08b56fa`。本批先处理长样本暴露的前置缺陷，不修改关系增长、同意条件或多伴侣规则，也不新增 LLM 调用。

## 发现与修复

将无人世界从十四日延长到二十八日后，种子 314 在第三周触发 `SUPPORT_ANOMALY` 的 `major_action_reserved` 断言：白天支持逻辑检查了剩余行动、出击和支持预约，却未检查后续加入的相处预约、校园活动报名。尝试扣费时被统一行动规则正确拒绝，旧断言却使整个推进失败。

现在先在可用性投影中检查双方相处与校园活动预约，给出不泄露对方具体日程的拒绝说明；执行时再对复制的行动预算调用同一权威扣费函数，确认两人都能扣费后才实际结算。预检失败没有任何一人的实际扣费、关系变化或支持回执。正常预约仍需本人主动取消，不自动覆盖别人已经答应的活动；原支持预约、出击与知识/本人陈述要求保持有效。

## 专项证据

五项新增 Python 专项已通过：

- 帮助者或被帮助者的真实相处预约分别阻止支持，投影与命令结果一致。
- 两种身份已有校园活动报名时同样受到保护。
- 隔离旧投影漏检的情况，直接调用实际处理器；第二位参与者有预留时，第一位也不被部分扣费，未产生事件。
- 显式取消相处后可正常支持，双方各付一次主要行动，没有免费恢复或重复结算。
- NPC 自动支持不会抢占已预留的行动。

夹具使用真实月相事件、真实路径和正式邀请/报名命令；为了检查执行前的瞬间，明确构造下午起点并清除过期活动投影、刷新论坛时段，不将这种夹具宣称为自然世界。初轮夹具时钟错误与空事件容器类型断言错误已修正，未改变运行规则。

新增后台 Godot 专项通过：实际场景找到目标并听取陈述 → 支持按钮因预约被禁用、显示未扣行动 → 手机主动取消本人的相处 → 重新查看目标 → 支持可用且真实扣费，时钟不变。未弹出前台窗口。
