# 第 9 步第三批验收：跨日回访与实际物资需求

2026-09-08；仅开发分支，不合并 main。第 9 步仍在进行中，第 10～12 步尚未因此完成。

## 已实现

真实滞留现场关联持久回访；表世界当面/已有手机联系；未回应不等于失踪；受影响者脱离后主动报平安；生命/专注缺口决定本人近况陈述；真实贫困且缺绷带时转入既有物资请求、同意与物理交付系统；实际恢复才结束回访。玩家面板、手机、私人年表与调查情报已接入。

回访不推进时间、不消耗主要行动、不治疗、不转移物品。正常休息仍全部恢复，不增加强制吃药条件。已结案历史不会因以后不相关的新伤而重新打开；无关人物看不到完整案例、夜相现场 ID 或地点。

## 验证

- 新增 9 项 Python 专项通过：无回应/隐私、真实脱离伤势、重复查询、意愿和联系人、NPC 主动回访、检查点/旧档、完整内核原子性、贫困 NPC 向玩家发出待答复物资请求、实际休息后结束与防止旧事件重开。
- Godot 新增 `welfare` 流程通过：实际推进过夜、明确伤势条件、真实人物按钮和 HTTP、本人陈述/调查来源、无重复写入、时间和行动不变。伤势与同地展示是明确 UI 夹具，不伪装成自然样本。
- 程序和契约冻结后的最终全局回归全部通过：67 模块 / 618 项 Python 测试，38 项 Godot 流程；没有缩减测试范围。日志末尾分别为 `GLOBAL_OK 67 618`、`GODOT_CHECKS_OK 38 flows`。
- 全部本批测试关闭付费 API；Godot 后台 headless，不弹前台窗口。Windows 原生环境未测试。

## 七天无人干预样本

seed 42，28 个时段，没有玩家接任务、交易、对话或战斗，没有预植受困者。

- NPC 完成 147 个任务、处理 27 个异常现场。
- 第 2 天晚间自然形成 1 次真实受困；第 3 天晨间救援超时，人物按原规则在实际地点脱离并留下伤势。
- 第 3 天产生“仍需照顾”的主动陈述，第 4 天实际状态恢复后产生“已经恢复”的主动陈述；共 2 个 `CAMPUS_WELFARE_REPORTED` 事件。
- 此案例没有触发新增物资请求，不把“提出请求”的专项等同于自然发生采购/交付/治疗全链。
- API 调用 0。案例之后保持结束，未反复刷消息或重新制造伤势。

这证明一条来源真实、跨日且无玩家参与的后果链能自然执行，不足以证明世界已具有丰富长期故事性。持续纠纷仍未在这个样本中出现，部分区域压力仍触顶；不标记长期平衡或完整第 9 步验收通过。

第二个种子 seed 7 同样运行七天：NPC 完成 163 个任务、处理 32 个异常现场；4 次受困、3 次救援超时、7 次近况报告，4 条回访案例最终均为已恢复。该计数不替代每条案例的采购/医疗全过程评测；同样没有 API 调用。
