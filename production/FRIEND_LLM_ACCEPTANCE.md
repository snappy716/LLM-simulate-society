# 基础 20 人＋额外好友：LLM 运行时验收

2026-09-08。开发分支 `codex/campus-demo-architecture`，不合并 main。当前规则详见 [NPC 认知运行时](../design/NPC_COGNITION_LLM_RUNTIME.md)。

## 实现范围

- 基础 20 名深度 NPC 持久保留；玩家额外接入的好友不挤占基础名单，不再有 6 人上限。可接入人数仍受实际校园人口约束，不会凭空生成新 NPC。
- 关系门槛：NPC 对玩家亲近度 ≥ 45、信任 ≥ 45、冲突 ≤ 40。由人物面板主动接入，免费，不批量导入联系人。基础人物、已接入人物与关系不足者显示各自原因。
- 接入后持续保留，关系下降不会删除记忆或自动退出；行动仍可拒绝。新好友从下一次跨日参与完整规划，不重算当天。
- 玩家面对面或手机主动对话可使用模型，包括普通 NPC；不限制每日/时段调用次数，不因普通聊天自动占有长期名额。
- 默认关闭后台每日/时段/用途请求配额与每日 Token 配额。旧数字仅供显式启用预算的诊断策略；游戏公开状态对应配额为 `null`。
- 每名深度 NPC 的一次跨日请求中，分别组合四个时段的合法选项；日内不再次完整推理。保留受保护职责、任务承诺、真实位置、资源与行动次数校验。
- 20 人及额外好友均有请求机会，失败回退规则，不再因旧预算只允许少数人参与。普通互动的游戏冷却和数量规则仍存在，不等于 API 调用配额。
- 旧存档按精确内容版本/manifest 迁移，保留旧觉醒者、记忆、资源、事件、当天日程和 RNG，不覆盖原档。

- Godot 后台验收：34 项流程全部通过，见 [Godot 日志](validation/friend-llm/godot.log)。
- 通用模型适配器的本地 HTTP 协议验收通过，见 [协议日志](validation/friend-llm/http.log)。
- 测试未读取个人接口配置，付费请求为 0。以上结果不代表真实模型效果已验收；Mac 无窗口验证完成，Windows 实机验证待补。

专项覆盖：

- 额外第 7 名好友成功接入且保持基础 20 人；关系三个边界由后端拒绝/接受；重复接入不重复计数。
- 21 名深度 NPC 全部获得跨日规划，日内零后台规划请求；关系下降后好友持续保留。
- 普通 NPC 连续 15 次玩家对话仍通过模型提供者，不增加深度名单或推进时间。
- 四个时段可组合不同选项，缺少时段或串用 ID 则拒绝；系统原候选 ID 与执行参数不可被模型短编号覆盖。
- 原有长期目标的无人参与推进与完成得到回归验证。首轮曾发现短编号覆盖系统原编号，现已修复，未放宽任务执行校验。
- Godot 真实 HTTP 命令验证关系拒绝、普通 NPC 对话、按钮等待/结果、20→21 人与跨日过场；使用明确关系夹具和假提供者，后台无窗口运行。
- 本地 HTTP 协议服务器验证实际通用适配器的 JSON 请求/响应、20 个不同 NPC 的日程请求、普通 NPC 对话及错误身份拒绝，不冒充真实语言模型表现。

## 复现

```sh
python3 -m unittest discover -s tests
python3 production/run_godot_checks.py --godot /path/to/Godot
python3 -m production.check_llm_local_protocol
```

Godot 可仅运行 `--flows friend overnight_flow`。所有自动验收均为无窗口模式，不抢占前台；本轮没有原生可见窗口截图。

## 仍需真实模型验收

本轮证明的是程序通路、校验与执行能力，而不是“故事多样性已经极大提升”。真实 Key 的当前有效性、所选模型的日程 JSON 成功率、性格与记忆一致性、多日演化差异、Token 花费和跨日等待仍需实际模型测试。模型仍只能使用已实现的合法行动；任意新行动类型、自然语言承诺自动变成任务，不在本轮完成范围。

保留并发 1、单次提供者超时与输出长度保护。跨日 HTTP 等待窗口随深度人数扩大，不是提速措施；人数增多时费用与等待可能同步增加。Windows 仍为目标平台，当前仅在 Mac 开发环境完成后台验证。
