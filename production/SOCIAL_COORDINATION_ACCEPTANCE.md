# NPC 自主邀约与次日反馈验收

日期：2026-09-08。分支：`codex/campus-demo-architecture`，不合并 main。

## 交付内容

- 过夜日程生成后，有联系方式的 NPC 通过现有手机线程发出邀请，对方规则确认/拒绝。
- 确认基于双方独立生成的兼容地点与时段，不修改日程，不取代受保护职责或现有任务；同人同段不重复约会。
- 日内按实际活动完成、位置、层、冷却、忙碌和合法意图执行。提前拒约不再强行兑现该意图；普通偶遇仍保留。
- 约好但未能执行时发送一次取消通知；确认见面不等于接受具体合作内容，不虚构完成结果或惩罚关系。
- 邀约与执行回执随存档保存；次日模型收到本人上次尝试结果，不读取他人邀约内账。
- 人物面板询问安排会区分“想找人”和“已约好”，也支持被邀请者本人披露；陌生玩家不能读取 NPC 私有手机线程或邀约账本。

详细规则和未覆盖部分见 `design/NPC_SOCIAL_COORDINATION.md`。玩家即时 LLM 聊天、基础 20 人之外接入好友、不设聊天调用上限均未改变；协调答复和取消本身不调用 LLM。

## 自动与 Godot 验收

专项 6 项通过：兼容日程确认、日程/关系拒绝、无联系方式不发送、互相邀请防双重预约、被打断不传送与取消幂等/存档、跨日反馈与日内零调用。

人物面板新增后台 Godot 验收：用明确的兼容日程夹具生成真实手机邀请，再通过真实人物面板按钮和 HTTP 命令询问安排，确认展示“已经和约好的同学约好碰面”、免费询问不改时钟、公开快照不包含私有邀约账本。该夹具不证明自然样本一定会赴约，也不是付费模型测试。

最终全局通过：64 模块 / 594 项 Python、35 项 Godot 流程。证据见 `validation/social-coordination/python.log`、`godot.log`。Godot 全程 headless 后台运行，未弹出前台游戏窗口；未进行 Windows 原生机器测试。

## 真实三日无人干预测试

使用已授权个人 DeepSeek API，经生产兼容接口和非思考选项调用 `deepseek-v4-flash`；种子 42，200 NPC、20 名基础深度人物，连续第 2～4 天。模拟期间玩家不参与，结束后在独立状态上抽测 2 次玩家对话，再运行同种子离线对照。

| --- | --- |
| 有效完整模型日程 | 60/60；240/240 时段选择有效 |
| 实际 API 请求 | 71：60 规划、8 自动交流措辞、2 玩家对话、1 连通探针 |
| 实际 Token | 输入 149,639；输出 9,086；合计 158,725 |
| 自动日内调用 / API 错误 / 响应拒绝 | 0 / 0 / 0 |
| 模型社交意图 | 43 |

| 实际模型选择的互动 | 22：5 接受具体互动、17 拒绝具体互动 |
| 26 项已确认见面的结果 | 16 实际交流（4 接受、12 拒绝具体内容），10 未碰面 |

“拒约”与“赴约后拒绝合作”是两种结果，不能混为一谈。全部 43 项意图都有终态回执：15 未碰面、17 实际互动被拒绝、5 接受、3 提前拒约、2 冷却、1 条件变化。

240 个深度人物时段都有活动完成，215 个活动/地点与原计划相符；25 个被必要物品短缺（18）或已接受任务（7）覆盖。正式执行器仍高于社交意图。

## 如何解释结果

本轮实际模型社交为 22 次，上一轮为 16 次；这是单个种子的两次随机模型样本，不足以证明该改动稳定提升多少。真正新增且有证据的是：双方知情的确认/拒绝、真实失败通知，以及下一天可用的自身反馈。

已确认邀约仍有 10/26 未碰面，说明仅核对初始日程不够，物资、任务改道和临时情况仍会打断。任务完成数与离线相同，互动来源的完成任务也均为 4，不能声称自主故事丰富度已经显著提高。

下一批可基于这些失败原因实现有限的替代时段协商/履约准备，但需继续尊重职责、任务、行动与目标人物自己的选择；本批不擅自加入强制赴约、自动改写日程、主线或无限重规划。

本轮只有上述一轮 71 请求的付费三日测试，自动回归与 Godot 夹具不使用真实 Key；实际金额由服务商账单决定。密钥只通过终端隐藏输入进入内存，没有保存到游戏设置、仓库或证据文件。
