# 第 11 步第一批：同检查点七天因果对照底座

基线 `e5283e3` 已上传开发分支。此次新增生产验收脚本与自身测试，不改游戏规则、不增加聊天或觉醒调用上限。

## 如何避免虚假的对照

- 从种子 42 自然推进，第一次出现真实月相异常后捕获完整世界和随机流；没有人为设置关系、知识、事件、结果或行动预算。自然起点在第 3 天上午，所以正式七天比较的是第 3 天上午至第 10 天上午，而不是把前置两天算进七天。
- 两分支分别恢复同一检查点，核对源检查点与实际恢复状态的摘要；保留代码版本、运行源码哈希和内容版本。正式命令不复用存档中的旧编号；初次试跑曾因此被内核拒绝，修正的是测试编号而不是幂等保护。
- 无人分支只推进 28 次时段。白天探索分支只用现有道路、同地点显示范围内的人、已有联系人及本人披露的主题；不使用审计对象的隐藏身份或远程位置去追人。
- 探索策略暂时只轮访阅览大厅、镜湖广场、学生中心、南门；每个白天时段最多抽样询问三人，然后按真实条件支持或阅读。这个取样量只在测试脚本中，不限制游戏聊天。
- 每次采样前后核对完整世界和随机流，保证检查论坛、手机及人物日志不会改变世界。审计的私有案例、参与者计划/资源与玩家可用投影分开保存；可用投影也不被写成玩家实际上读过。
- 检查 28 次正式成功推进、逐帧连续时钟、相同观察长度、无人分支无代办及 API 0。失败、拒绝、未遇见和没有支持保留，不为演示成功修改条件。

## 本批范围

9 项专项检查已通过。一日预跑中，NPC 自主夜间处置后接续白天支持，玩家尚未听取该事件；这只是短样本观察。最终七天、完整 Python/Godot 验收须在进程结束后填写。

## 最终结果（2026-09-09）

- 冻结后完整 `GLOBAL_OK 81 755`、`GODOT_CHECKS_OK 51 flows` 均退出 0。没有新 UI 控件，因此沿用全部 51 项实际引擎流程；不以纯 Python 冒充 Godot 验收。
- 同一起点两分支各 28 次正式推进，`CAUSAL_COMPARISON_OK`，退出 0；观察区间第 3 天上午至第 10 天上午，无 API、无人分支没有代办。
- 自然被审计人物吴修远的残像在第 3 天凌晨被另一名 NPC 处置；第 4、5 天上午得到持续支持；第 6 天上午使用第 4 天真实共同经历作锚点后稳定。全部有正式事件、行动与状态凭据，不是模型编写的故事摘要。
- 两分支中这起事件都由 NPC 解决，玩家没有听取本人陈述，也没有支持。探索分支实际走过 37 段道路、询问 43 次（41 次没有可确认的经历）、读书 2 次，确实发现了另一起事件。
- 被审计对象在一个采样时点与探索玩家同地点，但有限取样没有询问他，且玩家没有其联系方式。因此不能归因为“NPC 不可见”或“整个游戏没有发现入口”，更不能声称本批已证明玩家改变这起事件。

证据归档 `validation/step11-causal/`：比较结果、源码哈希、精简链路审计、完整压缩原始检查点/两分支，以及完整测试日志。下一批须让测试玩家先观察当前已出现的人物、回应实际求助、使用支持预约并加入夜间选择，再做真实 LLM 分支；不通过给玩家隐藏人物位置或补资源来解决测试问题。

这不是完整第 11 步结论：仍需夜间/更广探索的玩家介入、真实 LLM 同起点分支及可理解故事的体验复核。尤其不能用有限白天策略未遇到某人，就断言整个游戏无法发现事件。

## 复现

从仓库根目录运行 `python3 -m production.run_causal_comparison --days 7 --seed 42 --output <不存在的新目录>`。目录已存在时拒绝覆盖。输出原始检查点、前置真实命令、两分支逐帧审计/玩家投影、实际命令与事件、比较结果。

本脚本显式使用规则提供者，不读取或配置付费密钥。Godot 验收继续后台 headless，Windows 原生发行仍未验收，不合并 main，不纳入私人设计文档。
