# 过夜并行优化验收

2026-09-10，开发分支 `codex/campus-demo-architecture`。只优化代码与接口设置，不推进主线或医疗/安保等新玩法，不合并 main。

## 本批实现

20 名基础 NPC 与额外好友的每日日程使用有容量依赖屏障的并行 HTTP 管线；玩家即时聊天、各人物完整四时段规划、独立记忆与人格、规则执行与结算保持不变。接口设置新增 1～20 的「过夜并发」，默认 10，旧设置自动兼容。本地 Ollama 保持串行。

候选准备、随机数、预算预留、返回核验、缓存、实际用量、事件和计划应用仍在世界事务线程；工作线程只执行该 NPC 的有界模型请求。返回顺序不决定世界结算顺序。只并行不重试、不多收费请求、不降低完整规划人数。

## 已获得的定向证据

- 第一轮既有相关测试 14 项通过。
- 新测试覆盖多日串/并行完整世界与 RNG 对照、相同输入和账本、超时/429/截断/无效身份/过期返回、20+3 人、日内不重排、世界线程核验、缓存、可选预算、父场所容量屏障、真实适配器请求协议、并发参数验证和重复过夜幂等。
- 新 Godot 流程 `parallel` 使用两个真实本地 HTTP 服务：Godot 调用游戏服务，游戏服务并行调用仅回环可访问的模拟模型。检查 20 名 NPC 全部四时段、无兜底、完整用量、过场、重复点击和日内不调用。不是实际付费模型。
- 模拟每请求等待 3 秒：默认并发的完整过夜 13.4225 秒，串行 67.6488 秒；两者均 22 次请求。实际 API/朋友电脑的 15 秒目标尚未实测。
