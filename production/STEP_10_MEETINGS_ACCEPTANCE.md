# 第 10 步第三批验收：预约后真正到场支持

2026-09-09。基线 `d28956e`。仅上传 `codex/campus-demo-architecture`，不合并 main，不纳入私人文档，不实施主线。设计见 `design/CAMPUS_ANOMALY_MEETINGS.md`。

## 本批交付

私人求助 → 双方同意时间地点 → 保护职责和行动 → 实际道路赴约 → 重新确认本人经历/意愿 → 共用白天支持行动。人物面板可发起，手机可远程接受/取消；NPC 与 NPC 可以无需玩家完成。预约不治疗、不到场不成功，取消无退款，过期不会自动诊断失踪。

新增 13 项专项；联合原白天 10 项和残像卡牌 8 项共 31 项。初测发现自动采购先于约见，把已答应的人带往食堂；现已保护当期预约。日程记录补齐候选计数，不放松原有世界断言。手机实测发现打开未读消息的已读请求尚在处理中，过早点击会撞上桥接忙状态；控件增加忙态保护，测试等待实际已读操作完成后再确认，不用固定延迟伪装成功。

收尾检查补齐跨日预约边界：未来预约不因其他时段暂时不可用而提前取消，例如正常夜相活动；到约定时段才复核真实状态/意愿，过期照常结清。停止本次未完成的旧全量轮次，补专项后重新冻结并全量测试；只用修补后最终日志验收。

Godot 新增 `meetings`（真实面板选择、发起、确认、取消）与 `meetings_phone`（真实 NPC 来邀、默认待回复、手机同意/取消）。真实双方寻路与共同支持由 Python 正式时段/同一行动验证，未注入到场或恢复结果；Godot 原 `anomaly` 继续验证实际面板支持。电话与面板的预约操作不扣行动、不推进时间。

## 边界

冻结后两种子七日均正式推进 28 个时段、退出成功。seed 42 / seed 7 分别完成任务 160 / 162，实际处理现场 35 / 33，真实残留事件 4 / 6，实际夜间切断外壳各 3 次。新增自然求助分别 14 / 25 次，本批样本均被帮助者婉拒，白天支持仍为 0；没有人为补足知识、信任或同意。两组 JSON 与跨日校验修补前正常样本逐字节相同。

因此，本批成功路径由明确知识/联系人前置下的正式行动证明，自然样本只证明产生了求助与拒绝，并未证明自然支持频率已足够。下一批应让本人真实披露和调查线索形成有理由的知识准备/支持目标，不通过降低门槛、窥视他人知识或伪造支持来提高数字。

基础联系人/知识的受控前置只用于覆盖成功路径，不能当作自然演化证据。自然样本不植入事故、不代替玩家、API 为 0。求助、拒绝、等待和真正完成分别计数。Windows 原生发布未测试，本轮 Godot 全部 headless 后台，不抢前台。
