当前状态：标准接口的并行日程优化已完成，本地 Python 855 项、后台 Godot 58 条全部通过。下方先保留优化前诊断，再记录实现和模拟对照；实际云端 API 是否达到 15 秒仍未验证。

## 优化前诊断（历史基线）

- `campus_daily_plans.make_daily_planner` 在人物循环中同步调用 `runtime.plan_day`；每次 HTTP 返回后才处理下一个人物。
- `content/npcs/cognition_policy.json` 的 `max_concurrent_requests` 为 1；当前每日规划没有并发调度器，单独修改这个数值不会自动建立并发。
- 日程之后还可能有 NPC 互动对白或提议的模型调用。只加速 20 次日程调用不等于整个过夜流程已经达到目标。
- API 是可配置的通用兼容接口；模型、深度思考、服务端限流、网络和额外觉醒人数均影响结果，不能承诺所有配置硬性 15 秒结束。

## 原定实现顺序

1. 记录真实过夜分段耗时：候选构建、日程请求等待、互动请求等待、世界结算、快照生成。公开性能摘要不包含 API Key 或人物私密提示词。
2. 把请求准备、网络调用和结果应用拆开。网络部分使用可配置且有上限的并发池，结果在世界事务线程按确定顺序核验/应用，保留用量、缓存、失败和去重账本。
3. 处理当前人物候选对先前场所容量选择的依赖；不能把共享 WorldState、随机数或任务锁直接放到多线程中修改。对可证明互不影响的请求并行，竞争和资源仍用统一规则结算。
4. 审查日程后的额外决策/对白依赖：独立请求同样并行；可合入既有日程意图的选择保留执行时复核，避免仅加速主批次后仍串行等待。
5. 根据实际 API 限流与单次延迟选择并发度和模型配置。非思考模式仅在所选服务明确支持且用户接受时使用，不擅自切换服务商、模型或丢弃人物选择。
6. 验证 20 名基础人物、额外好友、慢响应/429/异常输出、缓存命中、重复点击、存档、日程竞争和即时聊天；用可控 HTTP 延迟测试证明并行及账本准确，再跑完整 Python/Godot 回归。

15 秒是整次过夜命令的验收目标，而不是将超时设成 15 秒或只测模型调用。若模型单次推理就超过 15 秒，完整等待所有结果无法靠程序并发保证 15 秒；需要用户选择更快配置，或另行讨论可感知且诚实的等待体验。

保持：20 名基础 LLM NPC、额外好友、个体记忆与人格、完整日程、免费即时聊天及现有行动规则。不通过跳过人物、伪造完成、降低聊天调用次数来报出漂亮数字。并行本身不意味着 Token 减少；不得靠重复投机请求换速度。

本次测量付费 API 调用为 0。待确认朋友的 API 服务、模型、是否开启思考及深度人物数后，再确定真实配置下的验收样本。

## 2026-09-10：并行日程实现

用户确认朋友使用相同模型，并授权优化。本批保持现有接口、模型和思考设置，不读取或改写私人密钥。

- `simulation/cognition/request_jobs.py`：把网络请求从结果核验、缓存和用量账本中分离；工作线程只收到该 NPC 的有界请求。兼容接口的每次请求使用独立诊断状态。
- 仅标准兼容适配器自动并行并隔离诊断；派生的审计/自定义适配器默认串行且保留原实例，避免破坏全局网络拦截、预算停止及连续失败计数。扩展适配器须自行保证线程安全后显式声明支持并发。
- `simulation/systems/daily_plan_jobs.py`：默认最多 10 个独立请求在途，按人物稳定顺序应用结果。每个未决人物对每时段各地点及其父节点记录可能占用；若可能改变后续容量判定，先结算前面的请求再生成后续候选，保持串行随机数与候选规则。
- 缓存命中不发请求，预算预留和实际 Token 结账均在世界事务线程进行；无投机重试或重复付费请求。失败沿用真实错误及原有兜底，不把失败计作模型成功。
- 命中缓存时，在准备请求时固定已有缓存结果，并以无网络任务按人物顺序核验/记账，不能越过早序人物写入审计。准备时可用的缓存可能随后被容量淘汰，但已固定的结果仍按原请求完整验证；不会为此重发模型请求。
- 设置页新增「过夜并发」：默认 10，可调 1～20。旧接口配置自动取默认值；1 可回退串行。本地 Ollama 仍串行，避免本地推理资源争用。该参数不是每日/聊天次数限制。
- 并发属于当前接口设置，不改世界内容清单与旧存档版本。历史 `CognitionPolicy.max_concurrent_requests` 字段保留兼容；实际传输以当前接口配置为准。
- 保留已有提示词无损去重与输出约束；本批不再改变提示词、模型或请求内容。并行本身不减少总 Token，也不通过新增调用提速。
- `CognitionRuntime.last_daily_performance` 记录日程耗时、阻塞等待、请求耗时总和、在途峰值和容量屏障数，仅驻留内存，不进入存档、随机回放或人物记忆。

### 本批边界

实际模型 15 秒以内仍待实测，不能由以上模拟成绩直接宣称达成。后续提议决策/对白中有真实的先后依赖，本批没有跳过、虚构或推迟这些结果；它们仍在过夜完整耗时内。若日程已快而完整过夜仍慢，应继续定位这些请求，而不是缩短超时或隐性减少 NPC。

旧的派生审计适配器保持串行，不可用其耗时代表新游戏并发成绩；真实并行验收应走标准游戏接口。并发不降低每个游戏日的 Token 成本，关闭游戏也不能撤销已经发给服务商的在途请求。

全局回归和后台 Godot 真实 HTTP 链路验收记录见 `production/OVERNIGHT_PARALLEL_ACCEPTANCE.md`；未取得终态成功前不作为通过或已上传的证据。
