# 第 10 步第一批验收：真实人物异常与知情白天支持

2026-09-09。前置审计：`design/STEP_09_CLOSURE_AUDIT.md`；本批规则：`design/CAMPUS_ANOMALY_SUPPORT.md`。只上传 `codex/campus-demo-architecture`，不合并 main。私人文档不纳入本批。

## 实际功能

- 真实被困人物脱离现场后保存同一人物的外壳/心结/异常自洽度，不依据孤僻或没回消息判定异常。
- 本人可拒绝的当前陈述、私有证据、旧陈述不冒充当前状态；听取免费，不治疗、不推进时段。
- 白天现实锚定遵守实际见面、开放时间、对应理解 20、本人关系与意愿、双方任务/出击承诺和各一次主要行动。每天同事件一次，三次不同日支持可稳定本批残留；没有刷奖励、恢复生命或代写任务完成。
- NPC 找实际在场、已认识且具备知识的可信联系人，通过同一处理器执行；不自动操作玩家。本人已经掌握的陈述提供给私有次日规划，没有新增日内模型调用或玩家聊天限额。
- Godot 人物面板实际按钮、条件、日期和文本反馈；不暴露内部心理数值或受害者隐藏位置。

## 专项与问题修复

新增 10 项 Python 专项：实际源与重复同步；免费/隐私/来源/重复询问；双方成本与无生命变化；拒绝/知识/版本与原子拒绝；远程/夜间/关闭/目标无预算；三个不同日的状态链与旧陈述；NPC 同规则支持；检查点/损坏/旧档；不知情与失真陈述；正式阅读获得理解并扣实际行动。

三日连续支持测试是明确日期边界，不把直接设定测试日期伪称自然世界推进；真实时段推进另以无人样本及全局测试验证。新 Godot `anomaly` 夹具使用正式夜间受困/天亮脱离，知识与见面预约是明确测试前置，不预写支持结果。实际 UI 依次询问→支持→重新听取，验证私有视图、真实成本、无时间推进和重复禁用。联合人物面板三尺寸布局、近况回访共 3 项专项通过。

专项发现并修复：无显式开放时间的室外地点应沿用常开规则；Godot JSON 的整数版本可能是浮点表示，应接受数值相等的整数表示但仍拒绝布尔值/旧版本。收尾还发现异步询问未返回时切换 NPC，回调必须解锁新面板且不能写入旧人物反馈；新增实际切人断言并通过三项专项后，重新冻结并运行全局。前一轮未作为最终验收证据，没有放松正式意愿、知识或成本校验。

切人回调修复与专项通过后，重新冻结程序、UI、契约、测试。完整 Python 输出 `GLOBAL_OK 73 668`，完整 Godot 输出 `GODOT_CHECKS_OK 43 flows`，退出码均为 0。没有跳过已有模块，没有混用第一次运行与修复后的结果；最终运行期间仅更新文档。JSON 契约语法和 `git diff --check` 通过。

最终日志、专项和两种子逐时段记录归档至 `production/validation/step10-day-support/`。Godot 全套包含实际切换人物、私有报告、支持成本与重复限制的新版流程；全部 headless，没有前台窗口。Mac 实测不等同 Windows 原生发布验收。

## 七日无人样本

任务和现场结果与前批一致，没有为了让新系统显得热闹而制造支持。自然样本尚未同时满足知识、已有可信联系人、同地和空余行动；NPC 成功支持仅由明确前置专项证明。第 10 步后续应建立有意愿的求助/约见和夜间路线，第 11 步验证自然机会、介入对照与可感知故事质量，不能把“能执行”写成“已自然形成丰富救援故事”。
