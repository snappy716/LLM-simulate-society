# 跨日过场：夜色到清晨

## 玩家体验

- 仅在深夜结束、进入次日清晨时出现全屏过场。上午→下午、下午→晚间、晚间→深夜不播放。
- 深蓝夜空、月光呼吸、微弱星光、流动光点和校园剪影，沿用校园终端的蓝灰与暖金配色。
- 显示当前日与目标日，以及“正在结算夜晚，准备明日的日程”。等待较长时显示真实已等待秒数，不伪造完成百分比。
- 后端成功返回**次日早晨的快照**后，转为清晨色调并在 0.45 秒内淡回校园。没有最低播放时长，不额外等待完整动画。
- 请求失败、断线或返回日期不符时，显示可阅读的错误和返回按钮；不自动重发推进命令，不宣称已进入新一天。

月亮与建筑是装饰性过场，不替代世界中真实的月相、污染、地点与时间数据。没有修改休息恢复、NPC 日程、自由行动或模型调用预算。

## 程序连接

1. `SimulationBridge.advance_campus_phase()` 先执行连接、忙碌与快照检查，通过后发出 `campus_phase_started(clock)`，再发送原有命令。
2. 全局 `OvernightTransition` 仅监听跨日请求，不调用任何模拟命令。它随场景持续存在，不因进入室内而丢失结果监听。
3. 过场期间暂停场景活动，桥接 HTTP 与过场自身保持运行。输入遮挡阻止人物移动、手机/地图/设置快捷键及重复点击。
4. 原有 `campus_snapshot_updated` 先应用快照，`campus_phase_advanced` 再通知完成；过场核实日期后才淡出。
5. 关闭时恢复先前暂停状态和仍然存在的键盘焦点，避免把原本打开的手机解除暂停。
6. 忙碌期间的重复推进失败信号不被误当作当前请求结束。新的有效请求可清理已结束但尚未淡完的视觉效果。

跨日请求的 HTTP 超时至少为 180 秒，并按基础与额外深度 NPC 数量、单请求超时和自动互动规模留出等待窗口；收到结果或发送失败后恢复普通请求的 30 秒超时。这是单次请求超时，不是每日聊天次数限制。动画不会缩短计算时间，也不会掩盖超时。超时后的服务端操作可能已成功，因此提示先重连确认，不自动再次提交。

## 美术替换边界

当前使用代码绘制的轻量矢量形状，无新增视频、贴图或第三方素材，也没有额外 LLM 调用。后续可只替换 `NightSky` 绘制与文案排版，保留开始、等待、成功、失败、退出这组生命周期，不能让动画自身控制时间推进。

## 验证入口

`production/run_godot_checks.py` 已纳入 `overnight_flow`，实际离线服务推进四个时段并验证次日快照；同时用明确标识的等待/失败夹具覆盖长等待、布局、输入与恢复。

```sh
python3 production/run_godot_checks.py --godot /path/to/Godot --flows overnight_flow
```

原生窗口的 `--keep-open` 是测试脚本专用的延长等待展示，不会被正常游戏加载，不增加正式游戏等待时间。
