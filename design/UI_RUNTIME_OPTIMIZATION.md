# 校园 Demo：UI 与每日规划优化

日期：2026-09-08。范围：现有第 1–8 步的体验与性能；不推进主线剧情、不换引擎、不新增付费素材或模型服务。

## 参考项目与取舍

- [Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios)，研究版本 `984023ddac0d5e27624f2baacde6105e45de375f`：参考 `ux-review`、`ui-programmer` 对信息层级、交互状态、可读性、焦点导航、分辨率验收的要求。它是开发工作流，不是可直接套用的校园 UI 素材包。
- [Godogen](https://github.com/htdt/godogen)，研究版本 `05cebffc8b10c5817e8a3db495b82e7b6004ab84`：参考引擎指导、运行态验收、根据真实画面迭代的流程。它是游戏生成开发框架，不是本项目的运行时依赖。
- 保留 Godot GDScript 客户端、Python 权威模拟、现有七张地图和已授权 Kenney 图标。不运行参考仓库的安装、发布、清理脚本，不引入其 C#/.NET 或多代理工作流，不复制商业游戏界面素材。

## UI 落地

1. 共享主题继续使用校园深蓝灰、浅色文字与金色重点，缩小终端边框和圆角、补充背景阴影。显式设置中文系统字体优先级并检查正常/粗体字形，避免部分标题显示方框；未捆绑或安装系统字体，Windows 发布前仍须真机确认覆盖或提供授权字体。模拟规则仍在后端，UI 只展示状态、发送原有命令。
2. 常驻 HUD 收窄，保留日期、时段、行动数、生命、专注、污染和两个主要操作。重复的地点与免费操作说明收进提示；左上角使用简短键位说明，给校园和人物让出空间。
3. 手机保留游戏内概念，但打开后使用宽屏校园终端。首页分为校园生活、人物与世界、探索与系统，每组五项；常用尺寸下 15 个入口全部可见。保留搜索、键盘焦点、返回和关闭。
4. 普通信息页由外层滚动承载长文本；聊天历史保留独立滚动，以便固定输入与交互。战斗页左侧阵型、右侧指令与物品；准备阶段展示部署，正式战斗展示出牌，不显示无效空控件。阵型与手牌不再各自嵌套滚动。
5. 保留断线、请求中、失败、空数据、禁用原因和草稿保护。禁止伪造进度百分比；跨日提示“规划新一天”，日内提示“执行既定安排”。

## 每日规划与实际执行

| 时机 | 执行内容 | 自动模型规划 |
| --- | --- | --- |
| 新世界或旧存档首次缺少当日计划 | 本地规则补齐四时段安排 | 不调用 |
| 深夜结束，进入次日早晨 | 世界结算、更新需求与承诺、整理记忆和目标、生成新一天候选方案 | 仅此窗口允许完整自主规划 |
| 上午→下午→晚上→深夜 | 读取当天计划，走实际路线、执行行动、检查实际条件 | 不重新调用模型规划 |
| 日内论坛注意力与事件响应 | 查看/抢接任务、已接任务执行、紧急采购、同行邀约与规则互动 | 不调用完整模型规划 |
| 玩家主动聊天、手机提议 | 按原通用接口即时响应 | 不受每日自主规划窗口限制 |

每个 NPC 保存四个时段的意图，而不是预先写好四段“已经发生”的日志。候选由现有规则、性格、需求、课程、值班、社团和个人目标生成；接入模型的角色在预算允许时一次选择包含全天安排的合法方案。未接入、预算不足、超时或非法响应均回退规则方案。现有后台自动调用预算保留；没有新增玩家聊天次数限制。

任务、交易、救援、组队与战斗仍由统一行动执行，不能因计划存在而跳过资格、库存、金钱、所有权、路线、营业时间、主要行动和原子结算检查。当天情况改变后，可退回日常安排或记录真实受阻；不在日内重做全量候选搜索。新任务和即时事件仍可触发轻量响应，否则会破坏论坛陆续接单和无玩家世界运行的特色。

## 性能修改与兼容性

- 命令去重缓存原本保存嵌套可变结果，每次事务复制会再次深拷贝所有历史命令事件。新缓存保存不可变 JSON 字符串，只在重放时解码；读取旧缓存时自动转换。
- 保留事务草稿、校验、原子提交、RNG 确定性、事件日志和精确重放，不靠删除历史或跳过校验提速。
- 日程和当日标记随存档持久化，读档不会重新发起当天模型规划；旧档缺少日程时只补一次本地计划。新程序可读旧缓存，不承诺旧程序能读取新缓存。
- HUD 仅在连接、忙闲或版本变化时刷新可用性，避免每帧重复修改控件属性。
- 仍有跨日集中等待：这是把完整思考移到夜间，不是消除它。真实 API 延迟取决于服务商；本次验收全程离线/假提供者，不花费个人 API 额度。

## 验收方法

- Python：完整测试集，重点关注每日调用次数、计划保存、旧档补齐、目标失效、角色仍实际行动、非法模型回退、聊天、交易、任务、战斗、救援及存档重放。
- Godot：运行 `production/run_godot_checks.py` 全部流程，覆盖首页 15 个入口、三个窗口尺寸、键盘可达性、滚动、请求锁和战斗阶段切换。
- 实际窗口：用隔离设置和测试存档打开原生 Godot 游戏，查看 HUD、终端、战斗，并保留运行态截图。截图不是概念图，也不证明真实 LLM 的故事质量。
- 性能：同一机器、种子 42、200 NPC、离线连续 7 天，以 `production/benchmark_campus_phases.py` 分别测量修改前后，单独报告日内和跨日耗时。结果和测试记录见 `production/UI_RUNTIME_ACCEPTANCE.md`；不把后端耗时当成帧率提升。
