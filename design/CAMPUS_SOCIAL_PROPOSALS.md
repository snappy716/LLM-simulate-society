# 校园结构化社会提议

## 目标

普通聊天只表达人物态度，不直接创造队伍、任务协助者或约定。会改变世界状态的请求统一通过 `MAKE_SOCIAL_PROPOSAL`：规则层先验证渠道和前置条件，再根据关系、人格、压力及既有承诺计算接受或拒绝；LLM 只能润色已经确定的回复。

第一版支持四类玩家提议：

- `party_invite`：复用真实三人行动小队的资格、意愿、容量和承诺结算；
- `task_help`：要求玩家持有有效任务，接受后把 NPC 写入该任务的 `helper_ids`，并建立随任务完成或放弃而兑现/破裂的协助承诺；
- `meet_up`：建立可在后续时段兑现的见面约定；
- `follow_up`：只在双方存在未解决约定时可用，并把该约定结算为兑现或破裂。

## 渠道规则

面对面提议要求双方处于同一可见校园场景；手机提议要求已经交换联系方式，并在原有聊天线程中留下提议与回复。两种渠道均为免费行动，不推进时段、不扣主要行动。为了防止反复刷关系，同一玩家、NPC 和提议类型每时段只允许结算一次。

## 权威边界

提议记录、队伍成员、任务协助者、社会约定、关系和情绪变化在同一事务内提交；任何前置条件失败都会整体回滚。NPC 的回复可以由通用 LLM 表达，但提示只包含人物可见状态和规则层已验证的接受/拒绝结论，模型不能改写结算结果或新增事实。后台 NPC 调用预算与玩家自带 API 发起的交流继续分离。

## 当前 UI

玩家靠近 NPC 打开人物面板后，可以选择四类提议并正式提出；手机“校园通讯”也提供同一入口。行动小队页面不再允许隔空邀请陌生人：必须先在场景中见面并交换联系方式，再通过手机正式邀请。

## 下一步

加入 NPC 主动提议队列。NPC 只能从规则生成的合法候选中选择，玩家在手机或当面界面明确接受/拒绝；在玩家回应前，候选不得提前修改队伍、任务或约定状态。
