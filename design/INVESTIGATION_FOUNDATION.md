# 第 5 步：调查与证据底座

执行顺序以 `IMPLEMENTATION_ROADMAP.md` 为准。本批不添加导师主线，不预置凶手，不让大模型生成世界事实。

## 玩家如何体验

手机 → 调查笔记。查看当前区域公告免费；深入搜查检查现场实际物品和已经公布的任务处理记录，消耗一次主要行动。没有新线索时不扣行动。这里只检查现有事实，不代表搜遍校园隐私或保证解决谜团。

选择一条已知记录后，可以携带真实笔记本固定来源及当时的可信度；可以设为保密，或与同地点、同世界层的人当面询问、分享。证据交流同一对角色每时段一次，普通聊天不加调用次数限制。对方不知道、不愿意透露、已经知道时，不凭空生成新证词。

选择两条不同记录，填写自己的推测。推测始终标记为待验证，不会升级为世界事实，不会自动发给 NPC，不会完成主线任务。程序接口允许关联 2～4 条；第一版手机提供两条选择器。

## 数据和规则

- 真实事实：复用 `knowledge.claims`。来自真实公告当前状态、实际地面库存、已提交物品行为和任务完成事件。
- 个人认知：复用 `beliefs_by_actor`，保留消息来源、上游来源、可信度、转述偏差和传播次数。玩家视图只返回玩家掌握的信息。
- 调查账本：`knowledge.investigation`，存来源索引、可查公开记录、个人笔记、个人推测、保密清单和证据交流冷却。
- 保密同时作用于指定分享、一般自主分享、既有对话可透露信息筛选。不能只做 UI 标记。
- 现场物品只证明曾观察到某件物品，不自动证明谁放下、有什么动机。NPC 私聊和内心目标不会成为公开现场线索。
- 公告按所在校园区域可查看；当面证据交流要求相同逻辑地点。表/里世界的现场物品和处理记录分层隔离。
- 观察、询问、分享、整理、推测均免费。深入搜查使用统一行动预算，遵守出击预留；战斗中不可绕过战斗锁调查。
- 失败事务不改变证据、物品、角色、行动数、时间或随机流。所有新命令沿用世界版本校验和幂等性。
- 新账本按需初始化，当前格式的既有存档缺少此字段时表示尚未调查，不补造线索、不重置世界。旧战斗格式的拒载边界不变。

## 玩家与 NPC

两者可执行相同命令，拥有独立笔记、认知和行动预算。NPC 只可转述自己知道且愿意透露的事实。当前自主交流已经能传播真实物品行为等新记录，但 **尚未实现 NPC 自动制订并持续完成调查计划**；该能力在第 7～8 步接入。

## 本批边界

这不是完整案件系统。伪装、门锁/犯罪取证、证据证明规则、技能检定、多解法失心者、跨日自主调查与主线阶段推进没有借本批宣称完成。第 6 步将知识、阅读、课程、案例反思与能力/牌组成长连接；第 7～10 步再使调查推动 NPC 目标、局势和干预。

当前笔记是不会被后续转述覆盖的历史快照；它没有凭空提高事实可信度或取消所有遗忘。当前搜查不伪造概率检定：只列出程序已经实现且可检查的来源，未来新增隐藏线索必须附带真实检定与失败后果。

## 验收入口

- Python：`python3 -m unittest -v tests.test_campus_investigation`。
- Godot：`python3 production/run_godot_checks.py --godot /path/to/Godot --flows investigation`。
- 夹具只安排 NPC 所在地点；地面物品由实际 `DROP_ITEM` 产生，其余动作均通过 HTTP 和手机控件执行。
- 全局验收需冻结代码后运行全部 Python 模块和 Godot 标准流程；不能用夹具结果代替自主社会长期验收。
