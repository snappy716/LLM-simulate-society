# 手机联系状态：调查前置条件

第 9 步第五批。目标不是制造更多“失踪案”，而是让真实联系成为可信来源，避免被困 NPC 仍正常自动回答的矛盾。

## 玩家可感知行为

- 普通表世界、里世界手机联系不受层域限制。玩家聊天不增加每日/时段 LLM 次数上限，不消耗主要行动。
- 实际被困、正式战斗占用或生命为零的角色暂时不能主动发送/回复。不能把这一条件用于禁止所有夜间聊天。
- 给暂时无法回应的 NPC 发送普通消息仍成功，记录原文；不伪造回复、知识传播、关系收益或 LLM 调用。界面只说尚未回应，不显示隐藏原因、现场编号或秘密位置。
- 同时段可以继续发送，连续尝试只按实际尝试过的不同游戏时段计数；经过时段但没有再联系不增加次数。只有已交换联系方式的人才能联系。
- 对方恢复可行动后，由日内社会更新或时段执行发送一次规则确认。它只表示“现在可以联系”，不是 LLM 回答积压问题，不代表治疗、救援成功或任务完成。继续提问仍走正常对话接口。
- 不替玩家自动回复 NPC。手动正常消息也可以结束相反方向的“尚未回应”状态。

## 权威状态与保留

`cognition.messaging.pending_replies` 按发送者→接收者保留最新待回应消息编号；`contact_gaps` 保存该方向最近一段联系经历的首次/最近尝试时段、不同尝试时段数和状态。字段可选，当前兼容旧档不要求补造历史记录。

状态为 `awaiting`、`contact_resumed`、`record_expired`。前者必须有真实保留消息和待回应索引。正常回复/恢复确认结束等待；消息超出既有线程 80 条保留范围时安全结束待处理索引，标明记录已过保留范围，绝不冒充已回应。历史确认编号可能随正常保留裁剪，不能据此重发确认。

同方向多条待处理消息只确认最新一条，不为每条积压消息生成一轮模型请求。既有保留数量是存档/UI 记录策略，不是调用配额。

玩家快照只带本人线程、本人联系经历的状态和时段，不暴露 NPC—NPC 私聊、无法回应的内部原因或位置。原 `phone_message` 字段保持不变，新增的规则确认来源类型由 JSON Schema 明确声明。

## NPC 自主执行

继续使用既有真实联系人、社交需求、待办线索、位置和一时段同对冷却挑选交流对象，不从隐藏受困名单反向挑选联系人。选择发送者之后再验证其能否执行；只有实际发送后，接收方无法回应才形成联系经历。

未回应尝试不算完成一次谈话，不改变双方社交需求、关系或知识。统计分别提供尝试数、完成谈话数、待回应数与恢复确认数。日内确认是规则执行，不引入日内完整 LLM 判断。

本批不承诺所有结构化邀约/自动收据都已统一迁移，不将“上线确认”当成精细读回执；这些系统仍按各自正式行动条件验证。

## 后续边界

一次未回应不能证明失踪。本批只是后续寻访的可信前置，并未实现完整失踪调查或调查任务链。下一批须用本人真实失败联系/实际逾期承诺发起寻访；地点只能来自已知公开会面点或有来源的目击信息，调查者须实际到场，不能读取隐藏位置来完成任务。

最终专项、全局、Godot 与七天自然样本证据写入 `production/STEP_09_CONTACT_ACCEPTANCE.md`。受控被困测试与自然出现频率分开报告，不以“能运行”代替故事性评价。
