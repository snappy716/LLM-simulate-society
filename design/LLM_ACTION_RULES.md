# NPC 共用行动规则与自主选择协议

2026-09-09 用户确认的实施方向。状态：设计已明确，运行时接入与执行补强待下一批验收；本文件不能作为功能已经上线的证明。

## 核心分工

规则说明「当前能做什么、需要什么条件、会花费什么」，不替人物选择「应该去做哪件事」。LLM 根据本人的性格、价值、需求、情绪、关系、记忆和长期目标，在实际可行的选项中自主规划。程序核验、通行和结算；模型文本不是事实，也不是已完成行动。

同一套基础规则供每日规划、互动选择、面对面对话和手机对话使用，不能只给 20 名基础深度人物中的某几个人。额外接入的好友、普通 NPC 回应玩家时也使用适用的规则；更换兼容服务商或本地模型不另建一套规则。

## 共用规则清单

| 范围 | 模型应知道的规则 | 程序的权威来源与校验 |
| --- | --- | --- |
| 时间 | 一天分上午、下午、晚上、深夜。跨日时规划输入 `day` 对应的新一天，不把当前第 N 天错称为第 N+1 天。日内执行已有计划，不额外调用模型完整重排。 | 世界时钟、`action_economy`、每日计划账本 |
| 主要安排 | 每个时段有一个主体安排，可自主选择学习、工作、社团、委托、休息等实际候选。主要安排是计划用途，不等同于所有动作都扣一次主要行动。深夜仍保留可选性质。 | 当期候选、行动定义、日程和实际预算 |
| 行动次数 | 当前每时段基础主要行动次数为 1；应从运行时政策读取，不在提示词另写一套固定数值。人物已经消费或预留的次数必须显示并执行校验。不能同时完成两项都需要该次行动的活动。 | `content/actions/action_economy.json`、个人行动账本及预留 |
| 免费附加行动 | 普通移动、购物、吃饭、短暂聊天不消费主要行动；可以配合主体安排，不因为做完一次采购就默认整段结束。免费不等于无条件、物品免费或结果自动成功。 | 通行、交易、物品及对话处理器 |
| 可行选项 | 每个候选说明活动、地点、行动类别、必要资源和已知限制。候选排序/评分是参考，不是必须服从的选择指令。不能凭文本新增一个尚未实现的行动。 | 合法候选生成与响应校验 |
| 通行与地点 | 实体活动必须沿可通行路径实际到达，满足开放时段、进入权限及适用世界层；采购后去主体活动所在地也需要通行。 | 地点图、营业时段、入口与层级校验 |
| 物品与金钱 | 购买、赠送、使用和装备依赖真实余额、库存、持有量及容量。报价不是成交；成交要再次验证，原子交换。 | 唯一校园库存、财富、交易与物品行动 |
| 委托与承诺 | 任务需要真实可接取状态，别人已锁定的不可夺取；接受的预约可能预留主要行动。承诺、期限和职责会影响可用性及后果，不能说已履约而没有到场。 | 论坛锁、任务状态、出击/支持/社交预约 |
| 他人意愿 | 想与人见面不等于对方已经同意；可能没遇见、被拒绝、条件改变或有其他安排。不能把玩家或其他 NPC 当作可控制的工具。 | 实际地点、联系人、同意/拒绝和执行收据 |
| 信息边界 | 只使用自己知道的、带来源与日期的事实及自身状态。旧消息不是实时定位；不知道不等于不存在，未回应不等于失踪。 | 个人知识、主观记忆、已读消息和允许事实 |
| 说话与做事 | 对话能表达想法、请求和感受，但一句话不能直接产生钱、道具、任务完成、关系承诺或治疗结果。实际请求走对应命令。 | 对话事实白名单、命令与事件 |
| 受阻与后续 | 执行前重查现实条件；不满足则记录原因，执行已授权且仍合法的后续或兜底。不通过偷偷增加 LLM 日内调用或捏造成功来补齐计划。 | 执行器、幂等/事务、实际结果与次日反馈 |

休息是有效的主体安排；某次休息是否消耗主要行动、是否恢复生命/专注，仍以已有条件和处理器为准。不能为了「用满次数」让所有人深夜加班，也不能把一次免费购物解释成整段工作已经完成。

## 人物差异如何进入选择

- 给模型本人的实际性格数值和量表含义，包含外向、开放、尽责、宜人、情绪敏感、风险倾向、规则认同与利他倾向；不把「外向」硬编码成每天必须找人聊天。
- 同时提供真实需求、情绪、资源、个人目标、已知关系和自己的过往尝试结果。相同性格的人在缺钱、疲劳、朋友求助等不同情境下，也可以作出不同选择。
- 职业和学院说明身份、能力及既有职责，不代替个人动机；模型需要简要解释自己此次选择的理由，但理由不能新增事实。
- 不以「和规则方案不同」为唯一成功指标。履行已有承诺、选择休息、暂不交往也可能合理；要看选择是否可执行、有个人动机、真实留下后果，并能通过日程/日志/手机等入口被玩家感知。

## 下一批实现范围与顺序

1. 从权威状态构造共用规则上下文，在所有认知请求的共同入口注入；区分共享规则与角色私有信息，不泄露他人计划或未获知的异常信息。
2. 每日候选补充行动类别/费用语义，提示词明确主体安排与免费附加行动，并修正「当前规划哪一天」的表达。人物选择不以规则评分为强制命令。
3. 打通模型已选择主体安排的执行链，使免费采购不再直接顶掉整段日程；不固定续接「去上课」，而是复核这个人物自己选定的合法安排。采购失败也须保留失败和后续记录，不能无限重试或重复消费。
4. 检验规则/模型两类 NPC 共用预算、通行与结果；实际预约、受伤、任务竞争等造成的合法改动不能误算为程序故障，也不能伪称按原计划成功。
5. 专项、全量 Python、后台 Godot、真实 LLM 样本分别核对：请求是否看到了规则、人物是否作出选择、执行是否符合规则、玩家是否能看到真实结果。通过后上传开发分支，不合并 main。

本批不取消现有固定职责保护、不增加聊天配额、不新增实时全局规划、不让模型直接写世界状态，也不把公开规则说明自动当成 NPC 可以向玩家泄露私密事实的许可。更自由的多步方案可在这个闭环上继续扩展，而不能只增加提示词却保留错误的执行方式。
