# NPC 日程与人物日志系统

状态：第一版已实现

## 1. 目标

玩家查看 NPC 时，可以像查看人物生平一样阅读其近期行动轨迹、社会事件和重要经历，从而直观看见“NPC 即使没有玩家也在生活”。日志不是调试输出，也不是全知视角；它必须服务于观察、关系、调查和世界演化。

第一版查看面板分为三页：

1. **人物概况**：现有公开身份、当前位置、当前行动和可观察情绪；
2. **日程记录**：今天与最近七天实际完成的行动，按天和时段排列；
3. **重要经历**：任务、交易、社团、关系、受伤、夜相和剧情等高重要度事件。

未来日程不是默认公开。只有公开课程、共同社团、NPC 主动告知或玩家调查得到的计划才显示；其余位置显示“尚未掌握安排”，不能泄露秘密行动。

## 2. 三种信息必须分离

### 2.1 权威人物年表

由规则系统根据已经提交的世界事件生成，记录客观发生过什么。这是存档和重放的一部分，不受 LLM 改写。

### 2.2 NPC 主观记忆

位于认知系统中，允许遗漏、误解、遗忘或被污染。LLM 只能读取该 NPC 能记得和知道的部分，不能直接读取完整权威年表。

第一版已经通过独立聚合与 API 阻止认知层直读完整年表；真正的主观记忆生成、遗忘和污染在 To Do 第 12 步接入 LLM 认知系统时实现。

### 2.3 玩家可见人物档案

从权威年表中按玩家的目击、关系、论坛信息、共同组织、对话告知和调查结果过滤。它可以显示可靠、听说、存疑和未知四种认知状态，绝不把 `private` 或 `secret` 事件直接投影给玩家。

## 3. 日志条目

每条权威记录至少包含：

```text
entry_id
actor_id
day / phase / minute
category                  routine / social / task / trade / organization /
                          injury / night / combat / discovery / story
activity_id / event_type
scene_id
related_actor_ids
importance                0～5
outcome
visibility
summary_key + parameters
source_event_ids
```

日志保存结构化字段和本地化模板参数，不把已经拼好的自由文本作为唯一事实。这样以后可以更换 UI 文案、语言和模糊程度。

同一角色、同一时段的移动、活动效果和活动完成事件合并为一条日程记录，避免显示三次。第一版保留逐时段客观记录；以后记录量超过 Demo 的 28 天边界时，可在查询展示层把连续重复的低重要度活动折叠为“连续三日上午上课”。任务完成、关系破裂、社团晋升、受伤和夜相行动不折叠。

## 4. 可见性规则

第一版按以下来源解锁：

- 玩家同地点直接目击：显示可靠记录；
- 校园论坛、公开活动和公开场所的重要事件：显示公开记录；
- 共同课程或共同社团：显示对应公共日程；
- NPC 主动告知：显示“由本人告知”；
- 其他 NPC 转述：显示“听说”，并保留来源和可靠度；
- 调查、照片、交易记录或任务证据：显示带证据的记录；
- 宿舍私人活动、秘密组织和未被发现的夜相行动：保持隐藏。

开发模式可以查看完整权威年表，但正式玩家界面不得提供全知开关。

## 5. 技术方案

新增独立 `chronicles` 世界聚合，不把日志塞进 NPC profile，也不把它与 LLM 记忆混为一谈。权威事件提交管线调整为：

```text
行动处理器产生 EventDraft
→ 生成稳定 SimulationEvent
→ NpcChronicleProjector 合并并建立人物索引
→ 验证世界状态与日志不变量
→ 追加事件文件
→ 原子提交世界状态
```

这样交易、任务、社团、战斗等系统只负责产生事件，不需要分别维护人物日志。事件文件写入失败时，人物日志和世界变化一起回滚。

Godot 校园总快照不携带 200 人的全部日志。查看人物时按需请求：

```text
GET /kernel/npcs/{npc_id}/chronicle?cursor=...&limit=20&filter=recent
```

返回值只包含玩家当前可见的条目、下一页游标和可见性说明。第一版保留 Demo 的 28 天完整记录，并通过按人物查询和每页最多 50 条限制 UI 开销；跨阶段长期存档的重复折叠在存档性能阶段实现。
