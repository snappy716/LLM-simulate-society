# NPC 自主办事：第 8 步实施边界

本文包含已验收的第一批边界与后续执行设计，不代表整个第 8 步完成。验收状态以 `IMPLEMENTATION_ROADMAP.md` 为准。主线不在本步实施。

## 玩家应当感受到什么

不是 NPC 用文字宣称做过事情，而是任务确实被他接走，随后出现在任务地点；人物日志、论坛结果、物资、伤势和关系与实际执行一致。玩家不参加战斗或整晚留在表世界，其他人的行动仍会结算；玩家不能凭查看论坛读取他人的私人牌库、研究记录或实时位置。

## 依赖顺序

1. **后台共用战斗执行器。** 从已有任务、本人地点、进入资格和队伍开始；调用正式准备、部署、开战、出牌、敌方回合、药品、撤退与胜负结算。不另写“NPC 胜率判定后发奖”。战斗选择先用有限确定性策略，不逐牌调用付费模型。
2. **替换夜间任务自动成功。** NPC 经现有路线到达目标；战斗型目标必须有已结束战斗凭据，活动文本不能领取奖励。行动费用由第一次正式开战核算，不先扣一次日程活动再扣一次战斗。失败、撤退和天亮失效各自处理；NPC 败北不快进玩家时钟，按自然次日恢复。
3. **承诺、备战与集合。** 尊重玩家预约、已有独占任务、职责、伤势及本人意愿；从真实联系方式/相遇关系选择合作者，不自动操纵玩家或把全校角色拉来。采购必须有店、有货、有钱、可达；集合继续使用实际路线，缺人可调整或放弃，不虚构已到场。
4. **错峰浏览和接单。** 复用任务原子锁，在已有免费行动/世界活动推进节点逐批触发合法浏览与考虑，不引入精细分钟钟表，不按玩家先选或 NPC 先选分配。只观察看过的任务和可公开的信息；待考虑不等于已锁定，执行前再次检查。
5. **玩家可见结果。** 双论坛保留真实处理历史和已公开的结果，人物经历记录本人参与的行动；未进入夜相的玩家不能从新界面提前读到秘密。NPC 自主研究、求助与后续行动读取实际结果，形成跨时段延续。

## 验收条件

- 无玩家参与的真实多日运行中，至少覆盖实际准备、移动、战斗行动、资源消耗与任务结算；胜利不是唯一合法结果。
- 同一战斗输入由玩家指令或后台执行时，规则与资源计算一致。重复命令、存读档和事件投影不重复发奖。
- 药品不足、无行动、道路阻断、队员拒绝、任务被抢、战败和晨光到来不会制造幽灵队员、无限循环或整日模拟崩溃。
- 玩家参与的队伍不得被后台接管；后台失败不得改变玩家日期、恢复玩家状态或扣玩家资源。
- 付费 API 关闭仍有完整规则路径；已有 LLM 只在自身合法候选与知情范围内发挥作用，玩家聊天不增加次数限制。
- 每一批完成后完整 Python 回归、Godot 全量流程与实际窗口检查，再上传开发分支，不合并 main。

第 9 步再把这些真实执行结果接到持续局势；第 10 步补异常对象的证据/支持/净化等多解法。不能因为当前模板有敌人配置，就宣称所有调查和救援目标都已具备正确解法。

## 第一批运行时（已完成本批验收）

`campus_autonomous_combat.py` 是行动选择器，不是第二套战斗结算器。NPC 经原日程执行器实际抵达自己锁定的夜间任务地点，再使用同一准备、部署、开战、出牌、基础指令、知识洞察、药品、敌方回合及撤退处理器。队长可以是 NPC，不再要求每场战斗都有玩家上场；玩家自己的阵型仍必须部署玩家。

- 首批仅独立 NPC 单人出战：临时单人队伍在实际结算后释放，避免永久阻止玩家后续邀请。已有玩家队伍、其他队长队伍和多人队伍不会被后台接管；已约出击的角色不会另行出战。多人出击仍须下一批完成共同承诺与集合。
- 首次开战扣本人一次主要行动；同一时段已支付者后续不重复收费，不再同时扣旧的任务活动费用。购物、对话规则不变。
- 控制器只选择正式界面同样列出的合法牌、目标和费用，以伤害、必要治疗、护盾与洞察作有限排序。不读取隐藏抽牌顺序，不改血量来保证获胜，不逐牌调用模型。12 轮或 180 个控制指令上限只触发正常有追击代价的撤退，不自动获胜。
- 胜利仍由共用战斗结果完成任务；NPC 和玩家都不能用 `COMPLETE_FORUM_TASK` 绕开夜间战斗。旧日程活动完成事件不再直接发夜间任务奖励。
- 败北按正式救援流程回住处，伤势与物资消耗保留，等待世界自然推进到次日恢复；NPC 独立败北不推进玩家日期、不恢复玩家生命。昨夜参加人数包含提前撤离/被救回的人，天亮自动退出人数则只统计仍在夜相的人。
- 新任务保存真实战斗凭据，包含战斗 ID、胜败、轮次、参与者和时段；凭据与实际已结束战斗交叉校验。旧存档中已结束的历史任务不补造战斗记录，新执行不能走旧自动成功路径。
- 双论坛动态记录展示真实结果；玩家首次进入夜相前继续隐藏夜间论坛。后台战斗牌库与私人研究不投影给玩家，救援后的普通活动日志也不泄露秘密战斗细节。研习只取得实际参战案例，同一遭遇不重复算一份任务案例和一份战斗案例。

这不是全部第 8 步已完成：错峰浏览与接单、主动协同备战与集合、进一步自主调查及任务语义拆分仍须继续。当前通用夜间模板的战斗结果不能冒称已经实现调查、救援和失心者的完整多解法。

2026-09-07 最终验收：53 模块 / 516 项 Python 回归全部通过；28 项 Godot 流程及实际 macOS Metal 窗口通过。新增 9 项专项包括真实无人参与时段、资源守恒、手动同指令序列对照、重放/检查点、败北不推进玩家时钟、同段第二战不重复计费、玩家小队不被接管和伪造凭据拒绝。实际论坛窗口展示 NPC 三轮战斗后完成任务；没有付费 LLM 调用或 Windows 实机验收。

## 第二批：自主备战、同行承诺与联合执行（已完成本批验收）

- 白天下午，已经愿意/了解夜相、没有职责冲突的 NPC 可以为夜间调查购买一份治疗物资。复用正式商店库存、定价、容量和道路；买后至少留下 30 金钱作为生活余量。已有治疗物资便不重复购买；一天只补一份，每次时段最多处理 12 笔，未获机会者仍能在之后准备。购物不扣主要行动、不产生免费药品、不调用模型。
- 晚间已实际接到任务的 NPC 从现有联系人或同层同地相遇者中考虑最多 4 名候选，通过既有关系、性格、压力与夜相资格判断邀请。没有降低原接受门槛，没有把全校变成联系人；对方可以拒绝。既有独占任务、玩家队伍、保护日程、伤势和出击约定优先，最多三人同行。
- 接受后用共同出击接口预约当日深夜；当时段到来预留各自行动，其他时段仍照常生活。手机已有联系人之间留下邀请与答复；预约失败会通知取消，不保留幽灵队伍。取消、退队或任务变化会结束临时同行承诺，不凭空返还预算。
- 队长沿真实任务路线抵达后，共用集合/部署代码再次核验队员是否可达、愿意、健康且有预算；未到场或无预算者不能代记参战。实际队员沿道路集合，首次正式开战各支付自己的行动，之后使用同一牌组、费用、敌方回合、药品和结算；当段已参战者不再被日程执行器重复安排另一项主要活动。
- 胜利后仅在原任务奖励内分配：每位实际参战助手取得 `总报酬 // 实际人数`，队长留余数。实际参战者互信小幅增加；未参战者无报酬、无战斗案例。败北/撤退不发胜利报酬，物资与伤势不重置，也不推进玩家时钟。
- 任务动态记录包含约定者、实际战斗、真实参战者及每人的报酬；仍在受权限控制的里世界论坛中查看。没有把后台牌库、完整私人计划或实时位置公开给玩家。普通玩家不需要开启调试状态文字。
- 检查点保留同行计划、参战时段、补给日和真实战斗凭据；重复结算不重复发奖，伪造参战者或分配额不能通过校验。旧存档缺少本批账本时按空历史兼容，不补造旧故事。

自然样本（种子 46）：不预填友情、阵容、药品或胜利，连续推进 11 个时段，在第三天晚间出现二人约定，深夜实际共同完成战斗，并把原任务 28 报酬分为 14/14。这是规则关闭 API 时的实际可复现实例，不等于 LLM 已产生自主剧情，也不要求每晚必然组队。

本批还不含：错峰查看/接单、开放式自主调查、持续局势、多解法失心者与第 13 步主线。下一批仍按依赖顺序先补错峰竞争。

2026-09-07 最终验收：程序及测试冻结后，54 模块 / 529 项 Python 全部通过（`/tmp/campus-expedition-global-accepted.log`）；29 项 Godot 流程全部通过（`/tmp/campus-expedition-godot-accepted.log`）。13 项新专项包含三日自然协同、拒绝、职责、取消/失约、真实购物和库存、原报酬分配、缺席不获战斗收益、败北、磁盘检查点重放及伪造凭据拒绝。实际 macOS 图形窗口显示孙若水与陈雨澄共同参战、28 报酬各分 14，见 `/tmp/campus-expedition-visual-final.log`；没有付费 API 调用或 Windows 实机验收。

## 第三批：错峰浏览与原子接单（已验收）

- 删除原来在时段边界一次性查看/考虑/锁定的两套循环。表/里论坛使用共同的“查看 → 考虑 → 尝试接取”过程；每名 NPC 有自己的待处理阶段和间隔，关系承诺、职责、所在层域、路线、专业匹配和经济需求影响是否参与与选择什么。
- Godot 在线且空闲时每 4 秒提交一次 `ADVANCE_SOCIAL_PULSE`。手机和普通覆盖面板暂停场景时，论坛仍能更新；关闭手机也会更新。读取快照本身不写世界，更新由明确的可重放命令执行；不推进日期、四时段或分钟，不增加/扣除主要行动，不调用 LLM。网络/其他命令处理中不并发抢占玩家请求。
- 每次更新每个层域最多处理 6 名到期候选；先看至多 3 条真实帖子，后续更新才考虑，再后续更新尝试锁定。没有为玩家预留名额，也不在一开始让所有 NPC 把任务分完。NPC 只从自己看过、所在论坛可见的任务选择，考虑不占用任务；玩家可先接，NPC 也可先接，版本校验决定唯一所有者。
- 共同接单接口区分实际角色，不再把 NPC 的接单事件写成“玩家接下”。失去竞争或日程/承诺变化后释放考虑状态，不保留虚假的“正在考虑”人数。新接任务仍沿当前执行器在后续可执行时段实际办事；因为当夜任务次日上午过期，现阶段 NPC 深夜不新增无法在下一时段执行的当夜承诺。此限制来自执行窗口，不是给玩家接单优先权；进一步同段任务执行与调查语义仍属于第 8 步后续工作。
- 时段开始运行少量注意力步骤，切换前处理待考虑过程；无 Godot 客户端的规则模拟也会接单和办事，不依赖玩家打开论坛。切换前发生的事实保留原时段时间，切换后的事实记录新时段，事务版本仍统一提交；出击邀请按任务保留尝试记录，避免每次刷新重发邀约。
- 注意力进度、随机流、待考虑目标与任务版本随检查点保存；重复请求不重复推进。旧存档无注意力账本时从空待办初始化。玩家只能看到论坛允许公开的查看/考虑人数、锁定者及结果，不能读取 NPC 的私有注意力队列。
- 论坛动态刷新保留滚动/焦点；后台接单不会重建正在编辑的聊天表单或战斗选牌页。既有自动化流程关闭真实定时器以控制测试时序；专门的 attention 流程使用正式 4 秒定时器验证手机打开/关闭、真实分批接单、草稿与焦点保留、无时间/行动成本及夜间论坛权限。

本批不宣称新增 LLM 推理能力：它提供可验证的竞争与执行入口。后续继续自主调查、任务语义和已知证据驱动的计划修订，再进入持续局势、多解法和七天样本验收；第 13 步主线仍不实施。

## 第四批：实地侦察与任务报告（已验收）

三类侦察任务拥有实际现场和两项固定读数。NPC 沿现有合法路线到场，调用玩家同样的深入搜查与报告提交；搜查扣一次本人主要行动，提交不再扣费，来源须为本人实地核验而非公告、转述或战斗胜利。论坛留下实际处理记录，证据进入本人调查知识和成长案例，不把异常读数解释成主线真相。侦察不组建战斗队伍、不制造击杀；救援与封控的完整任务语义仍待后续。详见 `FIELD_RECON_RUNTIME.md`。

返回表世界会在明确的按钮提示下按原有放弃规则释放未完成夜间任务，已取得的证据与消耗保留。精确内容迁移保持已有任务、战斗和 RNG，不追溯生成旧现场；已实际用上一提交生成的存档验证。用户最新要求是在第 8 步完成后停下，并汇总各部分及各自实际截图，不继续第 9～12 步。

最终验收：56 模块 / 553 项 Python 全局通过（`/tmp/campus-field-global-accepted.log`），31 项 Godot 流程通过（`/tmp/campus-field-godot-accepted.log`），实际窗口显示任务完成、两项核对与真实报酬（`/tmp/campus-field-visual-final.log`）。13 项新专项与自然 NPC 调查、战斗/调查成长共存、任务锁释放、精确旧档迁移均通过。无付费 API、无主线、未做 Windows 实机验收。
