# 校园手动存读档（路线 2A 第六批）

## 玩家操作

在校园场景或学生中心大厅按 `T` 打开手机，进入“存读档”。三个手动槽分别保存独立世界进度。保存、覆盖和读取均有确认窗口；取消不执行操作。第一次启动仍生成新世界，需要玩家主动读取已有存档，不自动覆盖旧进度。

- 保存当前世界：保存整个校园，不只是玩家；覆盖有效存档前保留上一份备份。
- 读取所选存档：放弃当前未保存进度，恢复所选世界。
- 读取上一份备份：当前文件出问题或希望回到上次覆盖前时使用，不改写磁盘原档。
- 刷新存档槽：界面版本过期、另一个进程写过槽位或请求结果不确定时先刷新。

## 唯一权威与恢复边界

复用 `WorldState` 与现有 `campus-kernel` 检查点，不另建一份玩家钱包、库存或 NPC 状态。保存人口、时段、行动预算、关系、通讯、任务与锁、社团、队伍、战斗与牌堆、库存、报价与记忆、采购/补货订单、日志、知识和命名随机流，以及已执行命令记录。实际持久字段以 `WorldState` 为准，尚未实现的剧情/敌方 AI 不会因存档而自动具备。

服务器内的命令与存档操作串行化，世界和随机流在同一事务锁内捕获。读档先校验格式、校验和、内容版本、资源及全部已注册运行时不变量；准备好候选世界和随机流后才整体替换。当前校园内核没有外挂事件日志接收器，本入口不用于回退一个持续追加的外部事件日志文件。

运行中的世界版本在读档后单调增加，避免读档前的待执行请求误作用于新世界；因此版本号不是剧情时间，也不承诺读取后的世界版本号等于磁盘旧版本。已记录的完全相同命令仍保持幂等；复用相同 ID 却改变参数会拒绝。

Godot 销毁旧场景，清掉旧选择、日志查询和移动回放，然后按恢复地点重建场景。已绘制区域匹配七图；多个图片覆盖同一区域时优先保留保存时的有效地图。尚无对应美术的逻辑地点保留当时的展示图，不擅自修改权威位置。学生中心恢复独立大厅。落点采用现有地面/入口安全位置，**不是精确像素站位存档**，也不代表所有室内场景已建成。

## 磁盘与错误保护

- Godot 自启服务使用 `user://campus_saves`，由引擎展开为当前平台的用户数据目录；不依赖 Mac 固定路径。仅开发测试使用 `GODOT_SIM_SAVE_DIR` 覆盖到独立临时目录。
- 手动启动 Python 服务可传 `--save-dir`；不传时位于现有运行数据目录下的 `campus_saves`。连接外置服务时以该服务配置为准。
- 客户端只能选择 `slot_1`～`slot_3`；不能上传文件路径或任意场景路径。槽位文件及临时文件拒绝符号链接。
- `slot_1.json` 为当前版本，`slot_1.previous.json` 为上次覆盖前版本；其他槽同理。临时写入后替换，写入失败不先清空旧文件。
- 同一目录使用操作系统文件锁防止多个服务同时写入；槽位内容哈希防止确认期间文件被另一个实例替换。确认时的世界版本也必须一致。
- 如果当前文件损坏，读取失败保持运行世界不变。确认保存时将坏文件原字节另存为唯一 `slot_1.invalid-*.json`，不拿坏文件覆盖有效备份。界面明确提示原异常文件已保留；本批不提供删除接口。
- 原子替换用于避免半截 JSON；不宣称已经完成强制断电、磁盘损坏或 Windows 实机验收。也未实现自动存档、云同步、发布包升级迁移或任意数量存档。

## 兼容与密钥

API 密钥仅属于运行时提供器配置，不进入校园检查点。同一服务读档不更换当前连接配置；彻底关闭再打开后需要按现有设置入口配置模型。关闭 API 仍可读取世界并用规则运行，不需要付费模型才能读档。

第一版只迁移同内容版本校园检查点中缺少的两项附加交易政策：`food_reorder_nutrition=25`、`food_buffer_nutrition=[100,150]`。补齐在内存中完成，不改原档，不补发库存、资金、健康或人物。

旧城镇存档、未知内容版本、缺少校园资源系统的早期校园档，以及校验失败的文件均拒绝强行转换，保留原档。后续需要具体旧档样本、版本差异清单和确定性字段映射才能新增迁移；不能把拒绝加载说成“全部旧版本兼容”。

## 接口与验证

`POST /kernel/saves`；请求契约见 `contracts/campus_save_request.schema.json`。操作为 `list`、`save`、`load`；写/读需要槽位、期望世界版本、期望文件哈希和确认标记。`backup=true` 选择读取备份；展示地图只允许七个已知 ID。

专项：`python3 -m unittest tests.test_campus_saves -v`。Godot：在独立端口和空的临时存档目录运行 `game/tools/test_campus_save_flow.gd`，覆盖取消、保存、购物、覆盖、备份、读档和旧场景释放。长跑：`python3 -m tests.run_campus_trade_soak --days 7 --seed 42`，中途使用同一个玩家存档入口保存/读取，再继续钱货核对。最终结果见 `production/VERIFICATION.md`。
