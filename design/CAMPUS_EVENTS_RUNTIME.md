# 校园比赛与节庆运行规则

第 12 步生活内容子批，2026-09-10。复用 `campus_life` 的定义、报名、到场账本与手机日程，不新建奖品钱包或平行任务系统。验收状态见 `production/STEP_12_EVENTS_ACCEPTANCE.md`。

## 第一批可玩内容

| 活动 | 时间地点 | 实际结果 |
| --- | --- | --- |
| 校园观察挑战赛 | 周三/周六下午，室内运动馆 | 所有实际参加者结束后统一排名；同分并列，名次不由先后报名决定。名次 ≤3 且表现 ≥45 才入选，否则保留参与与可解释的未入选结果。 |
| 社团交流节 | 周六/周日晚上，镜湖广场 | 每人贡献来自自己的实际展示。至少三名真实参加者、总贡献 ≥180 才形成联合展示；人数或贡献不足则为小型交流，不凭空补齐背景观众。 |

报名人数不设额外上限，仍受既有地点容量、通行与个人日程约束。6000 人仅是校园背景，这一批不会虚构他们的出勤来制造热闹。玩家可以不参加，NPC 仍可完成整场活动。

## 操作与代价

1. 手机 → 日程与约定 → 公开校园活动，查看本人当前及随后两天的机会、地点、时段与条件。
2. 可免费报名、退出。既有出击、相处、支持、工作/课程等确认日程继续互斥检查；报名不传送、不奖励、不预扣资源。
3. 自己沿实际道路到场，消耗本时段一次主要行动。工具不消耗；重复命令、已完成场次、错误时段/地点均不重复结算。
4. 可个人参加，或明确代表自己当前加入的一个社团。社团骨干/负责人可以额外明确选择使用公共资源；成员身份本身不授予支出权限。玩家默认个人、无资源支出。
5. 实际到场时重新检查成员身份、权限、社团余额；已选支持消耗既有 `resources.current` 的 3 单位并增加原 `spent_total`。报名不会冻结公共资源；期间资源被其他活动用掉时，本次不扣行动、不记出勤，允许退出后改为无资源参加。
6. 时段结束后才确认结果。未到场、取消、错过均不获得名次、展示贡献或奖励；当天聊天、购物、吃饭与普通移动继续免费。

## 评分来源

实际行动获得成长之前冻结输入，以后成长不能改写已经发生的成绩。

`表现 = max(0, 属性项 + 学院技能项 + 既有练习 + 课程准备 + 工具 + 社团支持 − 疲劳影响)`

- 属性项：观察赛为 `专注×3 + 洞察×3`；交流节为 `表达×3 + 共情×3`，使用人物原始属性。
- 学院技能项：调用现有 `ability_modifier_for_check`，按活动的表世界检定标签匹配本人真实掌握的技能及等级；沿用“最佳技能 + 次佳半值、最多 6”的现有规则，不新建熟练度。
- 既有练习：观察赛读取已有学习活动次数，交流节读取已有社交活动次数，最多加 6；本次参加不计入本次成绩的练习来源。
- 课程准备：观察赛使用研究方法课程知识，交流节使用数据素养课程知识（用于组织、记录展示信息）；每 4 点加 1，最多加 6。没有准备也可参加。
- 工具：实际携带笔记本加 4，不消耗；临时失去工具会影响表现，不由报名时的旧库存保证加值。
- 社团支持：合法且实际支出的公共资源加 8；不能把只填写的社团名称或未扣除的资源当成支援。
- 疲劳：当前休息需求每 20 点扣 1。没有单独创建“竞技疲劳”数值。

准备改变表现，不保证获胜。所有人使用相同公式，无玩家加成、强制胜负或 LLM 填写成绩接口。当前是原型平衡，不声称竞技公平性或各学院平衡已最终定稿。

## 结果和后续

- 比赛入选/完整联展：既有喜悦最多加 3、成就需求降低 10；其他实际参与者喜悦最多加 1、成就需求降低 3，按原量表边界截断。
- 代表社团、结算时仍是该社团成员：向原贡献值增加 3（认可成果）或 1（普通参与）。这会成为后续社团成长的已有条件，但不凭空记社团例会出勤，不绕过骨干晋升的其他要求。
- 个人参加不获得虚构社团身份。退出社团后仍保留真实参赛记录，但不给不存在的成员关系结算贡献。
- 未入选能看到自己的准备明细，决定继续上课、训练、准备工具或改选活动。小型交流保留成果，之后可自行组织相处、邀请伙伴；本批不自动生成保证有人接受的后续委托。
- 名次和联展成果由参与账本推导，在同一账本中标记最终结果，重复时段处理和读档不会再次发放收益。

## NPC 与 LLM

NPC 在既有每日计划中获得这些合法候选。职责、主要行动、道路、开放时段和已确认约定仍先核验，不增加日内模型重规划。

动机考虑人物兴趣、价值观、是否有社团成果可展示及近期真实参加经历；不是统一强制参加或按固定人数补齐。普通规则 NPC 也能选择；20 名基础 LLM NPC 及额外觉醒好友通过原候选接口选择，执行仍由正式命令校验。

既有规划/对话请求在相关人物确实有记录时，附上本人最近三次比赛/节庆的真实结果或缺席事实；无相关记录不追加空字段。不会把其他人的私有准备、关系或资源余额塞进上下文，不增加请求次数、不限制玩家聊天次数。

## 手机反馈和隐私

- 机会详情显示规则；报名时的代表社团/资源选项保存于原参与记录。修改选择需退出后重新报名，不能覆盖已完成的选择。
- 本人参与记录显示成绩构成、已支出资源和结算贡献。
- 公开结果板按场次选择，固定高度滚动，不把数百条成绩一次铺开挤走其他手机功能。只展示参展姓名、代表社团、最终表现与结果，不公开属性、技能明细、疲劳、准备或资源余额。
- 结果公开事件进入既有事件/人物日志。看到公开姓名不等于自动获得联系人；原探索与双方交流入口保留。

## 存档和实现边界

新定义位于 `content/actions/campus_events.json`。内容身份变化使用冻结的 `campus_events_content.json` 迁移边：校验旧 manifest 和旧活动定义，只追加两类机会与启用时点，保持既有报名、课程、兼职、关系、钱货、时钟、RNG 和原文件不变。启用以前的日期不补造“无人参与”的历史活动或获奖者。

本批不包含比赛小游戏、专属动作、美术节庆场景、观众模拟、随机奖品池、主线任务、恋爱排他规则或 Windows 原生发行验收。数据定义和权威参与闭环可供后续定制内容复用。
