# 校园 UI 底座

执行入口仍为 `IMPLEMENTATION_ROADMAP.md` 第 3 步。本文件记录实现边界，不替代路线。

## 第一批：共用主题与真实状态

- `game/ui/themes/campus_theme.tres` 由项目 `gui/theme/custom` 统一加载。按钮普通、悬停、按下、禁用、键盘焦点和输入框、面板共用样式；`CampusPhone` 是手机外框的主题变体。
- 后续美术可替换该 Theme 的颜色、边框与材质，不必修改交易、人物或存档代码。保留手机应用的分类色图标、标题层级和少量语义提示色；本批没有声称所有局部样式都已抽离。
- 手机连接标识读取 `SimulationBridge.connection_state_changed`，仅表示本地服务是否连接。它不是互联网信号、电量或 LLM 可用性指标；删除无来源的百分比。不发起新 API 请求。
- 保持七图、人物、输入快捷键、面板互斥、暂停恢复、存档内容与所有结算不变。采用现有深蓝灰校园界面，不复制第三方游戏资产。

## 后续顺序

1. 人物检查面板已改为视口安全区域内布局，标题/关闭固定，正文与关系操作滚动，焦点自动跟随。手机、地图和设置现有尺寸仍在基础视口内，继续检查整体入口与状态。
2. 统一 HUD、手机、人物、背包、交易、队伍的返回/关闭、等待/成功/失败反馈。禁用必须有可理解原因，不能让假按钮看起来已实现功能。
3. 检查离线/断线、空列表、任务已被抢走、角色失去资格、背包不足等状态；事实来自权威投影，不由 UI 复制规则推算。
4. 全局回归及实际 Godot 验收后才标记第 3 步完成，再进入卡牌战斗完整闭环。

每批记录见 `production/VERIFICATION.md`。Mac 开发验收不替代 Windows 实机测试。

## 第二批：人物面板可达性

- 原 680×700 固定面板在 960×540 基础视口下会裁掉内容。现在最大尺寸保持 680×700，但以视口两侧各 16 留白限高/限宽；打开其他 NPC 时回到滚动顶部。
- 概况/日志内容仍有独立滚动区；关系、交谈和请求操作归入外层滚动区。标题与关闭按钮不随正文移动；键盘焦点进入输入框时自动定位正文。
- 没有增加查看权限、编造 NPC 日志或改变交谈、联系人、觉醒规则。空日志继续显示玩家已知信息边界。
- 三种窗口与真实校园 NPC 的布局、焦点、滚动、关闭恢复均有 Godot 验收脚本，不只做源码断言。

## 第三批：HUD 与连接失败反馈

- HUD 展示实际地点名、持久生命/专注、月相和污染，不再把活动/地点内部 ID 当作玩家文字。时段推进与表里切换的不可用原因通过提示给出。
- 连接中断或无效响应更新连接标识，等待重连时禁用 HUD 行动。客户端只重新读取快照，绝不自动重发变更命令；通信失败只说明结果尚未确认，不能承诺服务端没有执行。
- 有效的 409 等业务拒绝保留原原因，不错误标记服务断线。空响应安全解析，不向 Godot 控制台刷 JSON 解析错误。
- 此处不承诺跨进程服务崩溃后自动恢复所有状态，也未增加 LLM 请求或聊天次数限制；完整发布级断线/恢复仍在第 15 步验收。

## 第四批：手机长表单与操作提示

- 所有应用正文进入共用纵向滚动容器，返回留在顶部，关闭手机由文字提示改为可点击按钮并保留 T 快捷键。关闭/返回不改变主要行动预算。
- 未指定最小高度的只读信息区至少保留 160 高，避免战斗阵容/说明被挤没。选择器不再为最长选项撑宽整个手机；键盘焦点跟随滚动。
- 人物、课程、备忘录共用中文活动名称；界面文案映射不参与行动规则。已知活动状态译为完成/未能完成，未知数据不假装成功。
- 商城、私下报价、存档的主要禁用按钮增加原因提示，原有正文及服务端拒绝原因保留。
- 自动验收覆盖 14 个应用入口、三种尺寸、固定返回/关闭、长战斗信息区和不消耗行动。解锁后的实际图形验收已补齐并上传 `6d1852f`。

## 第五批：分类首页与可替换图标

- 手机首页改为校园生活、人物与世界、系统三组双列入口；统一继承项目 Theme 的普通、悬停、按下、禁用、焦点状态，替代独立彩色方块样式。
- 各入口显示图标、功能名和短说明；支持中文关键词搜索、无结果提示、滚动自动跟随键盘焦点。14 个应用 ID、内部功能和暂停规则不变，搜索不发送模拟或 LLM 请求。
- 图标采用 Kenney CC0 临时资源并保留原许可。分类、说明、图标路径集中在 `campus_phone_catalog.gd`，可在定制阶段替换。已有七图和人物美术保持不变。
- 参考方向：[P5R](https://persona.atlus.com/p5r/) 的校园日程/功能组织、[极乐迪斯科](https://store.steampowered.com/app/632470/Disco_Elysium__The_Final_Cut/) 的文字驱动信息层级；这是本项目的设计取舍，不是对其原界面的复刻。
- 第三步仍需其他面板的等待、空状态与错误提示一致性收口；本批不等于全部 UI 或整款游戏完成。

## 第六批：物品、交易、恢复反馈

- 三个页面共用处理中与结果文案；保留服务端具体失败原因，缺少结果时不编造失败或成功。成功但无附加消息显示“操作已完成”，未确认结果提醒先刷新状态，不自动重试。
- 物品页仅在自己等待操作时处理共享完成信号，避免闲置页面被健康/交易结果覆盖。三个页面均防止自身重复提交；这不是跨页面并行请求的完整请求 ID 关联协议。
- 健康页补齐返回住处、休息、恢复技能的禁用原因，等待时禁用选择器，生活需求显示中文。休息成本、恢复量、夜间禁用和物品结算不变。
- 专项使用明确标注的 UI 状态夹具验证等待、拒绝、未确认回退和闲置页面隔离；真实恢复/交易/供货服务流程另行验证，不把夹具当作 NPC 自主演化证据。
- 后续继续论坛、社团、组队等页面的等待与空状态检查，第 3 步仍不整体勾选。

## 第七批：论坛、社团与组队

- 论坛接取/执行/放弃、社团入退社/活动、队伍邀请/解除均在提交后锁定相关按钮，完成后恢复并显示权威结果。等待状态按页面保存，不因打开其他应用而重置。
- 满员队伍重新选择候选人不再绕过 UI 禁用；缺少联系人、候选人或队友时给出原因。社团数据缺失时清空旧选择，避免旧选项看起来仍可使用。
- 入社资格、地点、活动时间、主要行动不足、负责人不可直接退出等已有条件增加中文提示，不改变规则。
- 十二个社团的类型、实践技能和公共资源由共享显示词表翻译，内容 ID 和规则数据不变；未识别项使用中性中文标签。
- 剩余 UI 入口：战斗、通讯与人物操作的等待/错误/禁用反馈收口，之后再验收第 3 步整体。新战斗玩法仍属于第 4 步。

## 第八批：战斗与通讯请求生命周期

- 战斗按钮统一经等待保护发送；等待时锁定战斗页按钮和选择器，回包后按最新权威投影重建。部署、撤回、开战、结束轮、出牌和基础指令有条件提示，不在 Godot 计算伤害。
- 通讯发送、提议、回应等待状态不会被快照刷新覆盖；空联系人区分“未同步”和“尚未结识”。不增加聊天次数上限，防重复仅针对尚未返回的请求。
- 通讯与当面对话保留失败草稿；成功仅清除与原发送内容相同的文本，期间新增草稿不丢失。人物页补联系人和觉醒名额说明。
- 本轮第 3 步基础 UI 验收覆盖 HUD、主题、手机 14 入口、人物、物品、交易、队伍、论坛、设置和现有战斗界面，已完成。后续新增系统仍须同步交付 UI；精细美术、发布级错误恢复、完整键盘/辅助功能矩阵和 Windows 实机仍属于后续验收，不因本步完成而取消。

## 2026-09-08：现有功能的体验修整

- 参考 Claude-Code-Game-Studios 的 UX 检查项和 Godogen 的运行态验收方法；不更换技术栈、不推进实施路线的第 9 步。
- 当前入口已增至 15 个。终端改为三组各五项的宽屏首页，常用尺寸全部可见；详细页保留固定返回和关闭。战斗页采用左右分栏，按准备/战斗阶段显示操作，取消阵型和手牌的嵌套滚动，隐藏内部卡牌类型英文。
- HUD 收窄，重复说明移到提示；共享主题补充中文字体优先级、粗体字形检查及终端阴影。仍需 Windows 实机验证；此开发版使用系统字体，发布前须验证目标机器的中文字形覆盖或提供授权字体。
- 每日完整 NPC 规划集中到跨日早晨，日内提示执行既定安排；免费操作、即时聊天、任务竞争、实际路线、交易及原子结算不变。
- 设计边界与验证方法见 [UI 与每日规划优化](UI_RUNTIME_OPTIMIZATION.md)，结果见 [验收记录](../production/UI_RUNTIME_ACCEPTANCE.md)。旧批次内容保留为历史记录，以本节为当前布局说明。
