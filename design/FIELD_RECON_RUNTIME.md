# 实地侦察与来源报告

第 8 步第四批，2026-09-07。已完成本批验收，不代表第 8 步整体完成。

## 玩家和 NPC 实际能做什么

三类侦察委托分别使用湖岸足迹、索引对照、月光交叉测量。任务发布时先在权威世界中生成对应现场，两项读数使用专用随机流生成一次并保存。公告只有请求和地点，不包含未检查的具体读数；模型或客户端不能提交自己的事实内容。

1. 先按已有论坛竞争机制取得任务锁；人物必须实际到达任务的具体地点，且处于夜相。
2. 在调查笔记中深入搜查：消耗本人一次主要行动，取得现场对照和异常两项读数。不把公告、别人的报告或战斗胜利当作亲自调查。
3. 回到任务详情提交报告：不再扣行动，校验任务所有权/版本、地点、当夜窗口及本人两项直接观察；报酬、关系、后续解锁和案例成长通过共同任务结算提交。
4. 实际报告记录留在论坛动态，完成后按钮禁用；具体证据仍属于个人调查知识，不向全部人物或玩家公开 NPC 的私有笔记。转述可以传播，但不能代替受托人的实地核验。

NPC 的任务选择器沿现有合法路线到场，调用同一个 `SEARCH_SCENE` 与 `SUBMIT_FIELD_REPORT`，没有专用自动成功判定。侦察任务不组建战斗出击队，不生成战斗或虚构击杀。本批不增加 LLM 请求、不给聊天设限；已有 LLM 仍受事实与合法行动约束，不宣称本批新增了开放式推理。

## 规则与边界

- 现场模型属于 `simulation/systems/campus_fieldwork.py`，题材与采样参数在 `content/situations/night_tasks.json`。现场权威状态在 `situations.field_sites`，观察事实和个人信念沿用调查/情报系统。
- 情报事实的主体现在可以是已存在的校园地点，不需要把地点事实伪装成某个人的经历。未知人物/地点仍拒绝。
- 同一地点可有多个采样点，一次实际搜查可以观察可见点的读数；只能结算本人持有的任务。历史现场留档，当夜过期后不能重新检查或提交当夜任务。
- 读数是游戏中确定的物理状态，不证明月光污染的起源、身份谜底或人物动机；这些仍需后续证据和故事设计。
- NPC 尚沿既有“接取后下一个可执行时段办事”规则；深夜不承诺下一时段已经过期的当夜新任务。更完整的同段执行调度仍需第 8 步收束审计。
- 本批只修正侦察的完成条件。救援、稳定、封控的具体对象与后续处理仍待下一批，不把调查或战斗模块当作这些玩法已完成。
- 返回表世界时，按钮明确提示放弃未完成夜间任务；后台复用共同放弃处理，释放任务并按既有社会规则结算。已取得的证据、消耗和伤势不回滚，正式战斗中仍不能绕开撤退流程直接离开。
