# 卡牌战斗回合底座

版本：Demo 程序定义 v1
状态：第 16 步第一、二子阶段已实现

## 1. 本阶段范围

锁定三排阵型后，玩家可以显式开始卡牌战斗。系统为每名实际上场的角色生成八张个人牌组和八个角色绑定的卡牌实例，使用战斗 ID、角色 ID 与洗牌次数命名的随机流完成确定性洗牌。相同种子、相同世界状态和相同命令序列会得到相同的手牌、牌堆与重洗结果，存档重放不会漂移。

个人牌组由两类来源组成：

- 角色已有的四项学院公共能力和一项专业分支；
- 所有人都具备的基础防御与非伤害指令。

牌组允许同一蓝图出现多次，但每张实牌都有独立实例 ID。每副牌保证至少一张防御牌和一张非伤害牌。本阶段不加入抽卡、稀有度或掉落卡牌。

## 2. 共享手牌与指令点

- 每轮每名仍在场的角色抽两张牌，三人队伍形成六张共享战术手牌。
- 卡牌仍绑定来源角色；来源角色倒下时，其抽牌堆、手牌与弃牌堆全部转入失效区。
- 第 1 轮共享指令点为 3，之后每轮增加 1，最高 6，并在轮次开始时补满。
- 未使用且没有保留标记的牌在轮末进入其来源角色的弃牌堆。
- 抽牌堆为空时，仅将该角色自己的弃牌堆按命名随机流洗回，不影响其他角色的随机序列。
- 每名角色可按所在排获得掩护、协同或观察基础指令，每轮只能使用一次，并与卡牌共用指令点和效果管线。

## 3. 权威状态与行动

新增统一行动：

- `START_CARD_COMBAT`：从 `ready` 进入第 1 轮，生成牌组、洗牌、补满 3 点并抽取手牌；
- `END_COMBAT_ROUND`：弃置未保留牌，增长并补满指令点，必要时重洗并抽取下一轮手牌。
- `PLAY_COMBAT_CARD`：验证来源角色、共享手牌、费用与排位目标，在同一事务中扣费、移入弃牌堆并结算效果；
- `USE_COMBAT_BASE_COMMAND`：验证人物仍在场且本轮未使用，随后通过同一效果管线结算。

每项行动都校验世界版本、战斗版本和当前战斗阶段，并在一个事务中同时提交牌区变化、随机数状态、事件和人物年表。错误阶段不会部分修改牌堆。

公共校园快照提供完整的灰盒战斗读模型，Godot 不自行洗牌、扣费或移动牌区。

## 4. Godot 灰盒交互

“夜战部署”页面在原有任务与阵型层级下增加：

- 开始战斗；
- 当前轮数与共享指令点；
- 来源角色、牌名、费用和类别组成的文字手牌；
- 结束本轮。
- 我方和敌方三排、敌方生命；
- 可用手牌、合法目标和出牌按钮；
- 每名上场角色的基础指令、合法目标和本轮使用状态。

该结构参考成熟 RPG 和卡牌游戏常见的“战场信息在上、共享资源居中、手牌与结束回合操作在下”的交互层级。当前目标是验证信息与操作流，最终卡面、动画、音效和布局美术仍可整体替换。

## 5. 尚未实现的边界

当前已经可以通过物理、技巧、认知和专业牌伤害敌人，也可以施加护盾、恢复生命或专注、揭示弱点和施加第一版干扰；最后一击会原子完成夜相任务并解除参战角色的战斗锁定。下一子阶段实现：持续状态生命周期、污染变化、敌方意图预告与敌方回合结算。完成这些之前，不将本阶段描述为完整可玩的战斗。
