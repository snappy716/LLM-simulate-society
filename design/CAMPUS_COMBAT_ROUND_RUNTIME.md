# 卡牌战斗回合底座

版本：Demo 程序定义，2026-09-07 更新
状态：新路线第 4 步基础 MVP 闭环已验收（第六批）；完整游戏验收以 IMPLEMENTATION_ROADMAP.md 为准

## 1. 本阶段范围

锁定三排阵型后，玩家可以显式开始卡牌战斗。系统为每名实际上场的角色生成八张个人牌组和八个角色绑定的卡牌实例，使用战斗 ID、角色 ID 与洗牌次数命名的随机流完成确定性洗牌。相同种子、相同世界状态和相同命令序列会得到相同的手牌、牌堆与重洗结果，存档重放不会漂移。

个人牌组由两类来源组成：

- 角色已有的四项学院公共能力和一项专业分支；
- 所有人都具备的基础防御与非伤害指令。

牌组允许同一蓝图出现多次，但每张实牌都有独立实例 ID。每副牌保证至少一张防御牌和一张非伤害牌。本阶段不加入抽卡、稀有度或掉落卡牌。

## 2. 共享手牌与指令点

- 每轮每名仍在场的角色抽两张牌，三人队伍形成六张共享战术手牌。
- 卡牌仍绑定来源角色；来源角色倒下时，其抽牌堆、手牌与弃牌堆全部转入失效区。
- 第 1 轮共享指令点为 3，之后每轮增加 1，最高 6，并在轮次开始时补满。
- 未使用且没有保留标记的牌在轮末进入其来源角色的弃牌堆。
- 抽牌堆为空时，仅将该角色自己的弃牌堆按命名随机流洗回，不影响其他角色的随机序列。
- 每名角色可按所在排获得掩护、协同或观察基础指令，每轮只能使用一次，并与卡牌共用指令点和效果管线。

## 3. 权威状态与行动

新增统一行动：

- `START_CARD_COMBAT`：从 `ready` 进入第 1 轮，生成牌组、洗牌、补满 3 点并抽取手牌；
- `END_COMBAT_ROUND`：执行已公布的敌方意图，结算护盾、干扰与倒下；未败北时弃牌、补点并抽取下一轮手牌，全队败北则转入救援。
- `PLAY_COMBAT_CARD`：验证来源角色、共享手牌、费用与排位目标，在同一事务中扣费、移入弃牌堆并结算效果；
- `USE_COMBAT_BASE_COMMAND`：验证人物仍在场且本轮未使用，随后通过同一效果管线结算。
- `USE_COMBAT_ITEM`：取用使用者自己的药品并支付共享指令点，治疗合法队友，同步持久生命；
- `RETREAT_CARD_COMBAT`：先结算已预告追击，再按幸存撤退或败北救援路径处理，不免费重置资源。

每项行动都校验世界版本、战斗版本和当前战斗阶段，并在一个事务中同时提交牌区变化、随机数状态、事件和人物年表。错误阶段不会部分修改牌堆。

公共校园快照提供完整的灰盒战斗读模型，Godot 不自行洗牌、扣费或移动牌区。

## 4. Godot 灰盒交互

“夜战部署”页面在原有任务与阵型层级下增加：

- 开始战斗；
- 当前轮数与共享指令点；
- 来源角色、牌名、费用和类别组成的文字手牌；
- 结束本轮。
- 我方和敌方三排、敌方生命；
- 可用手牌、合法目标和出牌按钮；
- 每名上场角色的基础指令、合法目标和本轮使用状态。

该结构参考成熟 RPG 和卡牌游戏常见的“战场信息在上、共享资源居中、手牌与结束回合操作在下”的交互层级。当前目标是验证信息与操作流，最终卡面、动画、音效和布局美术仍可整体替换。

## 5. 敌方回合与败北（2026-09-06）

- 使用既有 `battle.enemy_intents`，不另建敌方意图账本。开战及每轮更新时预告攻击排位和防御前威力，Godot 显示队员生命、护盾与敌方干扰状态。
- 首批为通用物理攻击原型，不代表八类怪物已经各有专属招式。初始威力为 `12 + speed // 2 + defense // 2`；攻击锁定预告排位，同排按角色 ID 稳定选取一人，排位已无人则落空，不暗中改打别排。多名敌人按速度、实例 ID 稳定结算。
- 沿用现有基础效果管线的减法防御原型：`max(1, 威力 - 目标防御)`，再扣护盾；干扰令下一次攻击威力减半并消失。护盾在敌方回合结束时清空。上述是当前程序原型数值，不是框架建议的最终百分比公式。
- 伤害通过共享 `change_vital` 回写角色状态，不随开新战斗或切换表里世界自动恢复。倒下者退出阵型，绑定牌全部失效，其他成员继续行动。
- 全队倒下：任务标记失败，支持承诺与来源钩子结束，不发奖励；解除战斗锁定并获救返回各自宿舍/住所。玩家参与时使用原世界时段执行器推进到次日上午，其他 NPC 的世界活动照常结算；救援休息恢复全队生命和专注，不返还物资，不扣次日上午的玩家主要行动。
- 救援 NPC 在恢复清晨不立刻跑去执行普通日程，后续时段恢复正常。共享敌方解析器本身不推进世界时钟，后续 NPC 后台战斗可等待自然时段恢复；这不代表 NPC 后台真实卡牌战斗已经接通。
- 救援记录、意图与资源随既有检查点保存。旧进行中战斗没有意图时，快照派生预告但不改存档，执行时补齐。重放和过期请求有测试。
- 战斗败北响应驱动 Godot 同步宿舍地图，并在页面上方显示“上次战斗结果”。不是只改后端位置。

## 6. 后续批次已落地的规则（2026-09-07）

- 正式战斗中不能由玩家跳时段绕开敌方；主动撤退先承受已预告攻击。幸存保留伤势与消耗、原时段返回表世界并释放任务；全队倒下则复用败北救援，不返还物品。
- 污染受击写回夜相人物长期值；护盾、干扰与抗性参与抵抗。30/60/85 投影危险阶段，净化牌可降低权威值；切换场景、开启新战斗和用绷带均不清污染。详见路线第四批。
- `USE_COMBAT_ITEM` 在己方回合使用既有治疗药品：实际使用者必须是本队已部署且仍可行动的角色，从自己的库存消耗一份，支付小队 1 点指令。同排或相邻排受伤且仍可行动的队友为合法目标；按内容中的 `heal_percent` 恢复并限制在上限内，第一版医用绷带为 25%。
- 满血、倒下、距离不符、库存或费用不足时拒绝且不扣资源；不会把食品和消毒液当作治疗药。队友使用最后一份职业绷带救人属于使用，不受“最后一份不能随意卖出”的转让保护阻止。
- 新入口不额外消耗世界时段或主要行动。库存、共享指令点、人物生命及战斗投影在一个事务中提交，事件记录实际恢复量。幂等请求和检查点恢复不重复扣药；生活背包入口仍不能在战斗中免费用药。
- 手机夜战页增加使用者/库存、合法目标和实际恢复预览，等待响应时锁定按钮。没有新增第二套战斗库存或全队共用药袋。
