# 第 10 步第二批：残像战斗与人物异常共用状态

2026-09-09。继承 `CAMPUS_ANOMALY_SUPPORT.md` 的真实人物/本人陈述/白天支持，不创建第二份人物或独立“已治愈”标记。完整多解法、身份锚点和求助约见仍需后续实现。

## 世界如何推进

真实夜间受困事件结束后，人物已有的月相残留可能在**原事件现场**显现为外壳残像。残像不是人物的肉身，不改变人物当前位置、生命、日程或进入夜相资格；人物可以继续自己在表世界的生活。

每晚从未切断的残留中选最多两例，计入原来固定的 20 个夜间委托，不额外加单。优先较久没有发布的事件，再按创建日期和稳定 ID 排序；同一事件至多一个活动委托。旧任务过期只结束当夜载体，不会把人物心结自动解决；外壳仍在时后续夜晚可再次显现。

公开任务只说明匿名旧现场、残像和处置目标，不发布受影响者姓名、私人经历、心结数值或实时位置。夜相论坛未发现时仍不可见。实际人物与任务的来源关联保存在服务端。

## 复用现有战斗与处置

残像沿用对应现象的敌人牌、意图、技能、三排布阵、费用、物品、撤退、败北和 NPC 同规则后台战斗；没有新建一个“点按钮掷骰子就赢”的旁路。

现场使用既有封控处理链：发布 → 错峰查看 → 原子承接 → 实际道路到场 → 部署/卡牌战斗 → 胜利 → 切断载体 → 正式任务完成。只有完整来源凭据才能改变人物账本。换人接手已压制现场时仍按既有规则支付处理行动；重复操作不再扣状态或发奖。

新任务没有额外金钱悬赏，收益是实际降低局部暴露、消除该外壳今后的显现、以及既有真实战斗案例知识。现有现场处置的地区压力与暴露后果仍生效。不因纯粹听说某人被救就奖励知识。

## 两条路线如何相互影响

| 环节 | 实际规则 |
| --- | --- |
| 白天削弱 | 一次有效支持使 shell 从 30 降至 20，再次降至 10，最后为 0；原知识、关系、本人陈述和双方成本继续有效 |
| 残像入战生命上限 | `ceil(原现象敌人生命上限 × 当前 shell / 30)`，最低 1；在准备战斗时固定，不公开人物内部状态 |
| 夜间实际胜利并处置载体 | shell 归零、coherence -20（最低 0），core 不变；还有残留则 easing。若心结已由先前白天支持解决，且本次后三项全为零，则 resolved；不凭空恢复生命或专注 |
| 撤退、失败、当夜超时 | 不凭空减少人物外壳或心结；保留既有真实资源损失与失败后果 |
| 外壳已切断 | 不再为同一事件生成新的残像，不重新生成已被击败的威胁 |
| 后续白天支持 | 在同一账本上继续处理尚未解决的心结；只有三项均为零才稳定 |

纯白天路线需要多日准备和机会。夜间路线能先移除现场风险，但不能用反复刷怪替代人物参与。已有白天支持能缩短后续战斗；完整昼夜联合的证据洞察与特殊结局代价尚未实现，不能将本批基础数值联系称为完整多解法。

人物面板中的本人陈述仍是带日期、版本的私有证据。其他人夜里处理了残像，不会让玩家的旧陈述自动变成当前事实；重新听取本人体验时，文字会区分“共同做过支持”和“残像被切断但心结仍在”，不冒称玩家做了未发生的事。

## 状态、契约与隐私

- 任务追加服务端 `anomaly_case_id`，现场仍为标准 containment，无 victim_id，不会递归制造新的受困人物。
- 战斗追加可选 `anomaly_origin`，保存来源、当时版本、外壳与实际生命上限；`battle_state.schema.json` 已声明，玩家战斗视图主动移除它。
- 人物账本的 history 支持 `day_support` 和 `night_containment`，后者保存真实战斗和现场凭据。白天日冷却独立计算，不因夜间处理发生就假装白天行动已用完。
- 守恒检查验证来源人物、原地点、对应现象、同事件唯一活动任务、实际敌方生命归零、胜利与现场处置、前后值和已完成任务的回写链。
- 旧当前格式存档缺少新字段时仍可用；不修改内容包 hash，不重写旧战斗。新投影仅用于之后创建的残像战斗。
