# 交友与恋爱：第一批运行规则

2026-09-10。用户确认：暂不采用“同一时间只能有一位正式伴侣”。本批属于第 12 步，优先于比赛与节庆；不制作固定人物剧情。

## 玩家入口与关系含义

手机 → 日程与约定 → 交友与恋爱。只列已有联系人，不自动添加全校人物。

- 可请求确认好友或表达恋爱心意；双方正式确认才建立关系。NPC 发给玩家的请求保持待回应，由玩家亲自选择。
- 不限制正式伴侣总数。每一对人物的好友关系、恋爱关系独立保存；结束某段恋爱不解除其他伴侣，也不自动删除好友和共同经历。
- 约会不是恋爱确认，恋爱也不是自动接受以后每次约会。已安排的活动仍走原有邀约、日程互斥、实际到场和双人行动结算；结束关系不会暗中替玩家取消独立活动，需在相处面板另行取消。
- 请求、接受、拒绝、撤回和结束关系免费，不推进时间、不刷好感。拒绝或退出不扣好感，不丢失真实共同经历。待回应请求三天到期；同一对、同类关系结束或拒绝后间隔三天再请求，避免反复催促；这不是聊天/API 限额。

## 第一版 NPC 判断

复用原有方向性关系数值，不新增第二套好感数据库。正式好友/恋人是双方确认的关系账本，而不是把单方面的好感显示成“互相深爱”。

NPC 根据自己的熟悉、信任、亲近、怀疑、冲突、恐惧、紧急需求与性格作出首版规则回应：确认好友需至少一次真实完成的共同活动；确认恋爱需至少两次真实完成的明确约会及更高的关系基础。复用已有的情绪敏感度影响谨慎程度，外向性影响自主发起频率；这些是可调整的玩法阈值，不是现实心理学结论或“送礼必成”公式。

玩家表达心意可以被婉拒；NPC 也不能仅凭玩家喜欢自己就自动认为双方相爱。已有其他伴侣不构成全局否决条件。本批不额外生成性别/取向设定，不新增排他承诺、嫉妒惩罚、劈腿事件或伴侣专属剧情。

## 自主活动与 LLM 边界

普通相处继续进入既有每日候选。已确认关系且本人愿意约会时，额外提供明确约会候选，不替代普通相处；LLM 可在原有过夜请求里选它，执行仍需对方回应和真实到场。没有新增日内推理或额外模型请求。

正式关系的自主发起与首版回应目前由规则驱动：每天早晨一次，依据本人关系和实际共同经历，按稳定种子及外向性决定是否提出请求；同日重入不重复执行。玩家不参与时 NPC 之间也使用相同协议。不能将这描述成真实 LLM 已自主发展出丰富恋爱故事。

模型日常规划与对话获得本人每对、每类关系的最新状态，包括已结束/已拒绝，避免旧的恋爱记忆覆盖已经结束关系的事实；不获得别人的伴侣名单或另一方向的好感。模型文本不能直接修改关系或伪造玩家同意。基础 20 名及额外觉醒好友机制、聊天不限次数均不改变；正式好友称号本身不绕过既有觉醒资格。

## 程序与验收

`campus_bonds.py` 保存可选 `situations.campus_bonds` 账本；旧档无该字段视为空。正式命令统一注册到内核：`PROPOSE_CAMPUS_BOND`、`ACCEPT_CAMPUS_BOND`、`DECLINE_CAMPUS_BOND`、`CANCEL_CAMPUS_BOND`、`END_CAMPUS_BOND`。命令版本、本人授权、去重、当前时段和参与者隐私均核验。

手机有独立请求反馈通道，记录进入现有私人手机线程和私有事件。全局伙伴总量不作为不变量；只禁止同一对、同一种类重复待确认/生效关系。

验收包括多位伴侣并存、独立结束、拒绝与冷却、真实约会来源、NPC 对 NPC、手机显式回应、旧档与检查点、隐私、异常参数、重放、全量 Python、后台 Godot 和七日无人样本。多日自然样本可以是零恋爱，不能通过注入好感、回执或付费 API 假造自然涌现。结果见 `production/STEP_12_BONDS_ACCEPTANCE.md`。
