# 第 9 步第三批：脱困后的跨日回访与物资求助

2026-09-08。承接真实夜间受困、实际救援或晨间未获救脱离；不是另建随机“失踪学生”生成器，也不是完整失踪调查系统。

## 因果链

1. 已有夜相系统把**真实人物**绑定到实际滞留现场，建立一条内部回访案例。未被告知的玩家/其他 NPC 不会获得案例、位置或夜相原因。
2. 玩家可以向当面人物或已有手机联系人发起 `CHECK_NPC_WELFARE`。正在夜相/战斗中的对方不能在此表世界回访中回应；留下的是“本次尚未确认近况”，不是失踪结论，更不是知道了异常地点。
3. 真实救援或晨光脱离发生后，当事人知道自己的经历，可以向已有、可信且当前能联系的联系人报平安。原有脱离伤势、救援道路、休息恢复继续由原系统结算。
4. 尚有生命/专注缺口时，陈述“还需休息或支持”；当前已恢复才报告恢复。该操作不移动人物、不治疗、不扣主要行动、不创造物品或奖励。
5. 如果当事人确实缺绷带且买不起，可向实际联系人发出既有 `REQUEST_MATERIAL_HELP`：NPC 按原意愿规则答复；玩家明确接受/拒绝；采购、保留量、寻路、交付和使用仍走统一规则。不能因发出求助就获得物品或回血。
6. 后续回访确认真实恢复后结束这次案例。未来不相关的新伤势不能重新打开旧事件；只有新的真实受困来源才能建立新一轮。

## 玩家能感受到什么

- 人物面板新增“确认近况 / 报平安回访（免费）”，显示实际结果；重开面板会显示自己最近获知的带日期近况。
- 既有手机线程保留询问、本人回复和物资求助；不会全校广播，也不会自动添加联系人。
- 本人愿意回应时建立 `voluntary_welfare_report` 陈述，进入现有情报/调查笔记来源；只有本人和收信人获知。它证明当时的陈述，不能据此推断全部经历或动机。
- 陈述不包含原夜相现场 ID 或位置；原始来源仅保存在内部案例，公开视图为玩家已知摘要。不同日期的旧陈述不被改写，便于玩家观察变化。
- 无相关回访案例时，按钮提示继续普通聊天；这不是替代随时可用的 LLM 对话。

## NPC 自主规则

当事人在实际脱困且处于表世界、没有参战后，按自己对已有联系人的信任排序选择一人，并尝试更新此前已告知者。每案每天最多一次主动更新、最多四名已有可信收信人；找不到合适对象就等待，不伪造人际网络。该限制是主动社会行为节奏，不是 API 调用配额。

普通人物也遵循相同规则。没有局外人读取秘密滞留名单后“凭直觉找到受困者”的机制；主动报平安来自当事人自己的真实经历。既有夜间规划仍只在过夜进行，这批不新增模型请求；私有事件与已知陈述进入既有个人记忆/调查通道。

## 数据与事务

- 可选 `situations.campus_welfare`：真实现场 ID→当事人、开始日、`unconfirmed / needs_care / recovered`、个人收到的陈述、最近主动报告日、关联互助请求和最近 24 条历史。
- 同一来源只建一次；无此字段的旧档按需补齐，不对超过前一日的终态现场追建回访负担。
- 世界事务检查人物、时段、联系方式和意愿；重复同段相同状态的查询不重复写消息或证据。状态真的改变可立即重新确认；结案后不刷效果。
- 内部案例状态与玩家已知状态分离：别人已获知恢复，不代表玩家自动知道；人物页显示的是自己的最近陈述及日期，不是世界真相雷达。
- 恢复由实际休息、物品或技能发生，仍遵守“休息全部恢复”规则，不额外要求吃药。请求一份物资不代表所有伤势已经解决。

## 当前边界与后续

专项与 Godot 有明确受控受困/伤势条件，结算、查询、消息与正式请求走生产代码；它们不能替代无人干预自然样本。自然样本结果见 `production/STEP_09_WELFARE_ACCEPTANCE.md`。

此批完成的是**真实受困事件后的回访和实际需求连接**，未完成长期失踪、安保正式报案、走访最后目击点、连续调查链或失心者干预。下一批继续这些可解释的后果及真实目标冲突来源，然后收束第 9 步，再推进第 10～12 步；主线不实施。
