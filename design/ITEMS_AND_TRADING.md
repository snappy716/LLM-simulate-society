# 物品与交易系统（文字灰盒版）

## 系统作用

本系统只实现能支持调查、交涉、生存、潜入与非凡故事的轻量物品经济。
当前目录包含 36 种有效物品和 5 家商店，不制作随机词条、拍卖行、复杂生产链或
完整宏观经济。

物品范围覆盖：食物、药品、日用品、工具、文件、钥匙、武器、简单装备、仪式
材料、魔药与唯一封印物。唯一任务物品与封印物不能通过普通商店交易。

## 权威状态与规则

- `content/items/catalog.json` 定义物品类型；`shops.json` 定义商店、营业时段和初始库存。
- `simulation/domain/inventory.py` 定义物品、背包、商店、报价和交易回执。
- `simulation/systems/economy.py` 是库存和金钱结算的唯一入口。
- 玩家与 NPC 使用同一个 `TradingSystem`；统一行动为 `BUY_ITEM`、`SELL_ITEM` 与
  `TRADE_WITH_NPC`。
- 所有检查先完成，之后才同时修改买方资金、卖方资金和双方库存。
- 任何检查失败都不允许发生部分扣款或部分移物。
- 唯一物品在全部背包中最多出现一次。
- 商店只收购经营类别内的物品；普通商店拒绝受限品和违禁品，地下市场可以接收这些物品。
- 商店按时段营业。库存低于目标时价格上涨，库存充裕时价格小幅下降。
- 每日结算会把商店库存逐步补到目标库存，不凭空补充唯一物品。
- 后续剧情动态创建的 NPC 会在首次访问经济系统时自动获得空背包。

当前货币以整数“便士”为最小单位，避免浮点误差。后续若需要显示镑、苏勒与
便士，只在表现层换算，不改变底层整数余额。

## 输入与输出

交易请求：

```json
{
  "actor_id": "player",
  "shop_id": "market_general_store",
  "item_id": "bread_loaf",
  "quantity": 1,
  "direction": "buy"
}
```

请求契约位于 `contracts/trade_request.schema.json`。成功交易输出 `TradeReceipt`、
`ITEM_TRADED` 世界事件和 `TRADE_SETTLED` 审计记录；失败输出明确错误码并记录
`TRADE_REJECTED`，但不改变世界状态。

## NPC 自主购物

旧 `SHOP` 不再操作 `object:market_food_crate`，而是占用 NPC 当前时段的一次行动，
并通过统一行动和 `TradingSystem` 完成最多一笔交易。决策顺序如下：

1. 根据饱食、健康/疼痛、精力、孤独、非凡材料需求和当前持有物计算物品需求分。
2. 只考虑 NPC 当前地点、当前时段正在营业且有库存的商店。
3. 按财富和经济压力保留最低生活资金；饥饿等紧急需求可以动用保留资金。
4. 经济压力较大时，优先向现场商店出售当前不急需且商店愿意收购的物品。
5. 买到确实需要立即使用的食物、药品或提神物后，从背包消耗并更新人物状态；
   其他物品保留在背包中。

因此 NPC 的自主购物会产生与玩家相同的 `ITEM_TRADED`、`TRADE_SETTLED` 和库存
变化，不再产生旧版 `ITEM_BOUGHT_AND_USED`。

## NPC 与 NPC 交易

非商人 NPC 也可以在同一地点进行交易。买方执行 `TRADE_WITH_NPC`，整个协商和
结算占用买方当前时段的交易行动，且最多成交一笔：

1. 卖方必须实际持有可交易物品，并根据自身需求、经济压力、数量和双方关系决定
   是否愿意报价。
2. 报价保存卖方、买方、物品、数量、单价、地点、创建时段、有效期和状态，但
   创建报价本身不移动或冻结财产。
3. 买方依据需求、资金保留额、报价、信任和怀疑决定接受或拒绝。
4. 拒绝只把报价标记为 `rejected`，不改变钱和物品；无人回应的报价在日终过期。
5. 接受时重新校验双方仍在报价地点、卖方库存、买方资金与负重，然后在同一原子
   操作中转移物品和资金。任一检查失败都不产生部分交割。

普通居民在私人交易成交后进入稳定的 2～4 天个人/单品冷却，同一对人物同一物品
在一天内也不会反复报价。杂货商、摊贩、酒保、酒馆侍者、药剂师和旅行商人属于
职业交易者，不使用居民冷却，而使用每日总额度与单品额度：他们可以从多个居民
处收货并再次出售，但不能无限刷交易。NPC 会保留当前生存必需品、已装备物品和
职业工具；例如医生、护士和药剂师不会自主卖掉最后一份医疗用品。

每次商店成交、私人报价、接受和拒绝都会写入 `TradeMemory`。后续报价会参考近期
成交价，买卖双方也会依据经济压力、信任、怀疑、社交性格、风险偏好、道德倾向
和报价溢价作出不同选择。交易记忆、普通居民冷却和职业交易者当日额度均写入快照。

事件链为 `PEER_TRADE_OFFERED` → `PEER_TRADE_ACCEPTED` 或
`PEER_TRADE_REJECTED`；成功交割另有 `PEER_TRADE_SETTLED` 审计记录。报价状态也会
进入世界快照，便于 Godot 调试面板和存档检查。

快照新增 `player`、`items`、`shops`，NPC 快照新增 `inventory`。Godot 按 `I`
打开文字交易面板，可以查看营业状态、库存、买卖价、玩家资金与负重，并以单件
进行买卖测试。

## 稳定物品实例、场景背包与统一行动

工具、钥匙、武器、装备、身份物品、笔记本和唯一剧情物品具有稳定 `ItemInstance`。
实例保存当前位置、合法所有者、耐久、装备槽、证据标签与来源事件。场景和容器也拥有
正式背包，因此丢弃与拾取不是删除/重建物品，而是在背包之间移动同一个实例。

当前文字灰盒行动为：

- `GIVE_ITEM`、`DROP_ITEM`、`PICK_UP_ITEM`；
- `EQUIP_ITEM`、`UNEQUIP_ITEM`；
- `PICK_LOCK`、`FORCE_OPEN`、`UNLOCK_WITH_KEY`、`CLIMB_WITH_ROPE`、
  `TRAVERSE_PASSAGE`；
- `PRESENT_IDENTITY`、`RECORD_INTELLIGENCE`、`THREATEN_WITH_WEAPON`；
- `PERFORM_LEGAL_RITUAL`、`PERFORM_SECRET_RITUAL`。

固定难度检定统一输出完全成功、成功、部分成功、失败、严重失败五档。物品只开放行动、
提供加值或改变后果，所有物品加值仍受“最强一项 + 第二项半值、总计不超过 40”的限制。

开锁失败可能损坏工具并留下开锁痕迹；撬门更可靠但始终产生高噪声与破坏痕迹；钥匙
无需检定；绳索开放屋顶入口但攀爬仍可能受伤。化妆盒必须先准备伪装，假证可直接出示
但暴露后成为证据，徽章必须装备到身份槽。笔记本把某个角色对某条事实的可信度与歪曲度
绑定到具体实例，记录版本的每日衰减显著慢于口头记忆。装备武器可进行威慑并参与旧袭击
检定，具体凶器实例会进入痕迹与事件来源链。

合法仪式需要仪式粉笔一份；秘密仪式需要仪式粉笔与灰白粉末各一份。配方先完整验证，
再一次扣除，缺少任一材料时不发生部分消耗。真正尝试后无论检定成功与否都会消耗材料。

Godot/本地服务保留 `/trade` 和 `/use-item`，同时提供统一 `/action`。请求使用
`contracts/action_request.schema.json`；响应同时区分 `performed`（命令确实执行）和
`ok`（行动结果成功），避免把检定失败误报为网络失败。Godot 按 `I` 打开文字面板后，
可以直接使用、装备/卸下或丢弃背包物品，不需要美术化装备界面。

## 上下游依赖

- 上游：世界日期/时段、NPC 职业与财富、内容 JSON。
- 下游：统一行动、Godot HTTP 桥、事件日志、世界快照、文字测试 UI。
- 不依赖美术资源，也不依赖 LLM。

## 边界情况

- 数量不是正整数、人物/商店/物品不存在：拒绝。
- 商店打烊、库存不足、资金不足、负重不足：拒绝且不改变状态。
- 商店现金不足以收购：拒绝。
- 非交易物品或商店不接受其合法性：拒绝。
- 唯一物品出现多个持有者、负余额、未知物品或非正库存：不变量检查报错。
- 存档和 API 快照始终输出物品 ID、数量、资金、商店状态、物品效果、装备和交易记忆。

## 可调参数

- 物品：`base_price`、`weight`、`stack_limit`、`legality`、`tradeable`、`unique`。
- 商店：`buy_markup`、`sell_ratio`、`cash`、`open_phases`、`desired_stock`。
- 背包：玩家 35 重量单位，NPC 25 重量单位。
- 稀缺价格：库存不超过目标 25% 时为 1.35 倍，不超过 50% 时为 1.18 倍；
  库存达到目标 150% 时为 0.9 倍。

## 验收条件

自动测试必须覆盖：成功买卖、资金不足、库存不足、负重不足、营业时段、位置、合法性、
唯一归属、NPC/玩家共用规则、自主购物、NPC 报价接受/拒绝、原子结算、API 快照
和交易契约。人工验收是在 Godot 主场景按
`I` 打开面板，购买一份黑麦面包，再出售初始麻绳，确认文字、资金、库存与负重
同步更新。
