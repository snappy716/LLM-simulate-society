# 第 12 步：比赛与节庆接入前核对

2026-09-10。用户确认暂缓独立安保服务，医疗验收上传后直接实现本批。本文是实施约束，不是已完成功能或验收报告。

## 目标

让校园机会形成真实取舍：有人报名、训练、准备道具，有人临时缺席；玩家不参加，NPC 仍能办成活动、取得名次并留下后续话题。学院基础能力与社团实践各有作用，不把两者变成同一套职业。

## 现有接入点

- `campus_life` 已有未来两天可见的公开机会、免费报名/退出、同一时段互斥、实际到场、主要行动和错过记录。
- `campus_study_work` 已在同一出勤记录中保存课程/兼职结果，并为前端过滤私人结算信息。本批继续使用该结果扩展位置，不另建参与者或领奖状态机。
- `campus_clubs` 已有十二社团、实际出勤/贡献、晋升、社团资源及共同战术。本批使用既有资源余额，不能另开无限活动经费或用报名凭空增加社团资源。
- 日程候选和手机日程入口已经接入该机会账本，可显示参与人数。玩家与 NPC 使用相同报名/到场命令与行动预算。

## 实施批次

1. **先做一项有正式结果的校园比赛。** 用现有运动场馆，读取实际基础属性、既往训练和实际准备条件。真实到场才提交成绩；本时段结束后统一结算名次，不能让较早执行的人直接成为赢家。并列必须明确处理，不能以人物 ID 优待玩家或固定 NPC。报名不发奖励；错过、取消和未达条件均不伪造比赛结果。
2. **再做一项协作型社团节庆。** 使用既有校园场景和社团，不创建强制全员参加事件。不同社团通过准备、表演或协助贡献不同作用，真实材料/组织资源不足会改变规模或结果；参赛能力高不自动等于节庆协作贡献高。完成后留下公开成果和本人实际贡献。
3. **串起后续机会。** 比赛和节庆结果能影响后续训练、社团贡献/关系或下一场公开机会。失败、落选与缺席也能解释原因并留下可继续参与的路径；不生成与真实结果无关的装饰性任务。

## 必须核验的边界

- 结果只读取本人/现场可用事实，LLM 不获得对手私密属性、日程或未结算名次。模型可选或不选，不新增日内全量规划请求。
- 真实准备应在参赛/演出前发生，报名、同一指令重放和反复打开手机不产生训练或资源。
- 公共榜单可以展示参赛者公开成绩；资金、个人属性明细、私密动机不随榜单公开。
- 不给玩家优先结算，不预先生成假 NPC 成绩；没有玩家参与也能完成正式活动。
- 检查现有“玩家可看未来两天机会、NPC 日程主要选择当天机会”的差异。需要准备期的有限名额活动不能默认给予玩家两天优先权；NPC 应能依据自己已知机会考虑未来报名与准备，也不能统一在一个时刻机械抢空。复用既有关注/报名/日程机制，不为此引入新的日内全量 LLM 规划。
- 兼容旧存档中的既有生活记录。若新增内容清单触发版本变化，要按现有迁移规则处理并核验实际旧 Godot 存档，不能仅放宽版本匹配。
- 每个主要批次仍须完整 Python、后台 Godot、适当多日无人干预样本；通过后上传开发分支，不合并 main。新增模型候选使用离线可控提供方验证，不默认启动付费 API 测试。

具体数值、场次内容和奖励来源在实现时依照实际资源结构确定，并写入正式运行文档；不能把这份计划作为本批完成证据。
