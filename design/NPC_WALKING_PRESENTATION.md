# NPC 动静结合与步速（2026-09-10）

用户本轮优先调整时段切换后的画面表现，不改变已确定的 NPC 选择、行动预算、地点结算或 LLM 规划时机。

- 校园场景原统一 220 像素/秒，移动层默认 320；现统一基准为 90，个体为基准的 82%～118%，约 74～106。玩家仍为 150，不跟着减速。
- 每个人的步速、起步延迟（0.3～4.5 秒）与中间节点停顿（0.4～1.6 秒）由人物 ID 产生稳定的表现层样式。仅使用独立本地随机器，不消耗模拟 RNG，不调用 API，不写存档。
- 最多四条可见路线同时播放，包含正在起步等待或途中暂停的角色。其余已排队人物保持静止，前一人到达后再出发；不在切换时段瞬间让整屏一起冲刺。
- 优先保留最多六名确实处于本区域且本次没有移动事件的人物，其余可见名额用于路线。没有真实居民时不凭空制造站立人群。总可见人数仍不超过十八。
- 到达后停住；刷新人物快照不把位置重新挪到另一个散布点。离场判断使用人物实际最终地点，不把尚未完成的预定活动地点当作成功到达。
- 使用现有模块化人物素材，按步速放慢移动动画节奏；这是已有动作的节奏调整，不宣称已制作新行走动作。玩家及其他角色默认动画倍率不变。
- 手机或人物界面暂停游戏时，NPC 路线与起步等待也暂停。再次切换时段、地图或读档会清掉上一轮队列，并忽略其失效回调，不把旧地图坐标带入新图。

这是权威地点事件的可视回放，不是新增实时社会模拟。等待动画不会阻塞玩家操作或额外推进时段；人物交互资格仍由现有后端真实状态判断。沿精确道路、碰撞、遮挡及逐个室内站位仍依赖后续场景细化，不因本次调步速宣称已完成。

验证：新增 Godot `movement_pacing` 流程检查真实时段 HTTP、稳定个体步速、分批并发、静止居民、界面暂停、节点暂停、到达后不跳位、失效队列清理及后端快照不变。拥挤场面的十四人样本明确为表现层测试夹具，不伪造自然 NPC 参与率。全局验收结果见后续 `production/VERIFICATION.md`；未通过前不上传。
