# 校园地点、人口与 Godot 导航灰盒

> 状态：地点语义、常驻人口、统一通行、日程移动与活动效果已实现
>
> 原则：室外连续行走，建筑切换场景，普通房间复用模板，关键房间保持独立

## 1. 地图粒度

校园按 10 个室外区域组织。道路连接区域时使用 `continuous_boundary`：玩家沿道路穿过边界后仍留在同一个室外 Godot 场景，只更新权威状态中的语义区域，不显示地点菜单，也不黑屏切图。

建筑入口使用 `building_entrance`，楼内房门使用 `interior_door`。二者只有在 Python 内核确认开放时间、权限和剩余时间后，才允许 Godot 请求室内场景。

当前共有：

- 10 个室外区域；
- 53 个建筑、室外点、固定室内点或房间组；
- 16 种可复用室内模板；
- 13 条显式室外道路，加上每个地点自动生成的父子入口。

普通教室、研讨室、实验室、社团室和宿舍房间是 `room_group + pooled`。它们在世界中具有真实地点和房号，但共享少量 Godot 室内模板。图书馆特藏室、心理实验室、心理档案室、观测平台、生化安全实验室、医院、监控室和旧教师住宅等任务关键空间保持固定地点。

## 2. 视频所示操作的对应规则

```text
沿右侧道路向上走
→ 穿过 Area2D 道路边界
→ TRAVERSE_LOCATION_PASSAGE
→ 内核更新区域 ID
→ 不切换 Godot 室外场景

走到左侧楼梯
→ 穿过建筑入口 Area2D
→ 内核检查位置、开放时间、权限与耗时
→ 加载复用大厅场景
→ 玩家放到 inside:<building>:entrance

从大厅出门
→ 对同一 passage 反向通行
→ 加载室外场景
→ 玩家放回 outside:<building>:entrance
```

每条通道都拥有稳定的 `from_anchor_id` 与 `to_anchor_id`。因此进入哪栋楼，就会回到哪栋楼的原入口，不依赖临时坐标或场景加载顺序。地点关闭后仍允许反向离开，避免角色被锁在室内。

## 3. 200 名常驻 NPC

生成器只使用 `npc_generation` 确定性随机流，不调用 LLM。相同世界种子会生成完全相同的姓名、人物 ID、学院、职业、宿舍房号、外观种子、技能、性格、需求、权限与初始经济状态。

构成为：

- 134 名学生；
- 66 名教职工；
- 20 名初始 `focused` 深度人物；
- 180 名普通 `persistent` 人物；
- 夜间状态为 78 名不知情、60 名敏感、40 名有能力、22 名愿意进入。

全校统计人口仍为 6000 人，其中 4000 名学生、2000 名教职工。未逐个建模的 5800 人作为背景人口参与容量、拥挤、舆论和经济统计；玩家是 200 名常驻 NPC 之外的独立角色。

每名学院人物包含本学院 4 个公共技能、1 个专业分支、1 个个人特质技能、社团技能（若参加社团）和 1 个关系协作技能。人物同时保存核心价值、道德底线、恐惧、执念、内在矛盾和身份锚点，供后续规则决策与 LLM 认知层共同使用。

## 4. 权限与居住

学生分别拥有东区或西区宿舍权限以及稳定房号，例如 `E01-101`。教职工拥有教师公寓语义房号。实验室、档案室、观测平台、监控室和维修工坊通过访问标签控制；生化安全权限只授予相关教师、研究生和助理，不默认授予所有本科生。

房号是语义实例键，不对应一份独立 `.tscn`。进入房间时，系统加载相应的复用模板，再根据房号、所属者和运行状态填充内容。

## 5. Godot 接口与组件

旧可玩原型继续使用 `/snapshot` v2。校园内核并行提供：

- `GET /kernel/campus-snapshot`：校园地点、通道、200 名常驻 NPC 和玩家位置；
- `POST /kernel/command`：严格的版本化统一命令；
- `TRAVERSE_LOCATION_PASSAGE`：玩家与未来 NPC 共用的通行行动。

Godot 侧新增：

- `CampusTransitionTrigger`：可放在道路边界、楼梯顶端或房门处；
- `CampusArrivalAnchor`：标记进入与返回的位置；
- `CampusNavigation`：根据内核回执更新语义地点或切换已注册场景；
- 独立校园导航灰盒，不替换当前旧版主场景。

灰盒入口：

```text
res://scenes/debug/campus_navigation_test.tscn
```

其中可以验证“右侧道路向上跨区、左侧楼梯进学生中心、室内出门返回原楼梯”的完整操作。正式校园室外图、建筑立面与室内美术完成后，只需注册对应 `presentation_key`，不需要修改通行规则。

## 6. 当前边界与下一步

本阶段之后已经补入四时段、主要行动预算、一周日程、NPC 自动寻路和活动真实效果；地图最终碰撞仍未加入，也没有把旧主场景替换成校园。后续顺序为：

1. 四时段与各时段主要行动预算（已完成）；
2. 日程模板和地点容量（已完成）；
3. 玩家/NPC 共用的路线移动行动（已完成）；
4. 普通 NPC 的规则决策与离线移动（下一步）；
5. 在稳定移动循环上接论坛任务、关系和组织。

日程与行动次数必须先于大规模 NPC 自主行为，否则人物虽然有身份和地点，却没有可靠的“何时能做多少事”的约束。

## 7. 一周日程与计划容量

校园内核现为玩家和 200 名持久 NPC 生成可重复的七天日程，共 `201 × 7 × 4 = 5628`
个计划槽位。12 套模板覆盖新生、三类学生与八类教职工，区分工作日和周末，并为每个槽位记录：

- 活动类型与主要/自由行动分类；
- 计划地点、优先级和原始申请地点；
- 因关闭、权限或容量发生的候补改派及原因。

容量分配同时检查具体室内地点和上级建筑容量，高优先级义务先分配，同优先级使用固定种子排序，
避免读取顺序改变结果。默认 200 NPC 内容无需改派；专项测试会把 10 名心理咨询人员同时安排到
容量为 8 的支持室，确认 2 人被稳定改派且没有超额占用。

本阶段只生成“计划去向”，不会直接修改 NPC 当前地点，也不会在计划阶段扣除主要行动。
下一步必须让 NPC 通过统一路线行动抵达计划地点，抵达后执行课程、值班等真实活动时才扣额度。
